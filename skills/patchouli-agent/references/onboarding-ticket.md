# 接入小票：一次性交换长期凭据

这是本地 Agent 的可选首次接入流程。已有有效凭据时直接使用，不默认重新签发。
小票在管理网页生成，为 16 个随机字符、5 分钟有效、一次成功兑换后失效。小票
可由用户发送到对话，但任何持有未过期小票的人都能选取普通凭据的权限和期限，
包括全部知识库与永不过期；不把它公开发布，不将它用作主 Token。

## 先确认，再兑换

缺失信息集中问用户：凭据名称、说明、有限期限或永不过期、读取范围、写入范围、
本机自定义环境变量名和持久保存位置。用户已明确的选项不重复询问。读写各自可选：

- `include`：只允许列出的知识库，空数组无权限。
- `exclude`：所有知识库，列出的为排除项；空数组表示全部，包含以后新建的库。

写入不隐含读取，不能擅自补读权限。用户要求全部读写时两项均为 `exclude []`。
不要因小票快过期跳过确认；过期就请用户生成新的小票，不代替用户猜权限。

## 兑换前发现知识库

服务根地址只能来自用户或已确认的本机配置。对 HTTPS 正常验证证书，拒绝跟随
兑换或发现请求的重定向，不把小票或 Token 发往新域名。以下接口不带主 Token，
也不使用网页登录 Cookie。小票作为 JSON 的 `code` 字段，不放 URL。

```text
POST /api/v1/onboarding/libraries
Content-Type: application/json

{"code":"用户提供的16字符小票"}
```

有效票返回 `{"libraries":[{"id":"稳定库ID","name":"示例知识库"}]}`；
查询不消费小票。仅列名称和 ID 供选择，无法用它读取文档。若用户选择某些库，
把名称对应到返回的准确 ID；同名时请用户确认，不从名称推造 ID。

## 本机脚本兑换与保存

先将脚本写入本地，再执行。小票可从本地交互输入或标准输入传入，避免写入
受跟踪文件、URL、日志或持久脚本。长期 Token 必须始终留在脚本进程内存和用户
选择的存储，不先输出给模型再保存。不要使用会展示 HTTP 正文的裸 curl、调试输出
或完整异常转储来兑换。遇到错误，只输出状态和已脱敏错误码。

```text
POST /api/v1/onboarding/redeem
Content-Type: application/json
```

请求示例仅包含合成占位值，期限为秒：

```json
{
  "code": "用户提供的16字符小票",
  "name": "Local editor",
  "description": "编辑资料的本机工具",
  "never_expires": false,
  "credential_ttl_seconds": 31536000,
  "read_mode": "exclude",
  "read_libraries": [],
  "write_mode": "include",
  "write_libraries": ["准确的目标库ID"]
}
```

永不过期使用 `never_expires: true`，省略 `credential_ttl_seconds`。请求不接受
主身份类型、归属库或旧 grants 字段。签发仍需服务至少存在一个知识库。
成功返回 201，JSON 含 `token`、`caller_id`、`credential_id`、`library_id`；
最后一个字段只是历史内部定位，不能据此推断实际权限。

执行脚本按顺序完成：

1. 先检查变量名合法且不会覆盖已有值，并检查目标保存位置可用；再发兑换请求。
2. 在同一脚本里取 `token` 并按[多凭据配置](local-token.md)保存。Windows 写 User
   环境变量；其他平台按用户选定的环境文件或 shell 配置保存。绝不把 Token 作为
   外部命令行参数或日志；不创建后台签发循环。
3. 从刚保存的位置重新读取，内存中核对与返回值一致，只输出保存成功／失败。
4. 用重新读取的 Token 调用 `GET /api/v1/auth/whoami` 和 `/api/v1/capabilities`。
   对照用户要求验证名称、凭据 ID、有效期、`library_scope` 和当前有效权限。
   即使保存成功，鉴权未通过也不能宣称接入完成；权限不符先报告，不自动扩权。
5. 下载受保护的 Skill manifest 和全部文件并验证 SHA-256、长度；遵循现有本地
   安装规则，保留用户私有配置。仅向获授权的 Skill／AGENTS.md／记忆位置记录
   变量名、入口、用途和读取规则，不记录真实小票或 Token。

401 表示小票不可用（过期、已消费或其他失效）；422 表示请求参数错误；429 表示
限流。失败时不反复猜码。当前限流为每服务进程发现与兑换合计每分钟 60 次，
多工作进程会各自计数；不是集群级防滥用保证。请求 JSON 上限 128 KiB。

兑换成功只返回一次 Token。如果网络断开、超时、保存失败，先停止自动兑换。
即使没有看到响应，服务器可能已完成签发；让用户在凭据管理页面按名称和时间
确认结果，再选择重新显示或吊销，不自动生成更多凭据。返回一次成功的小票不能
重放取密钥。主 Token 重置使未用旧票失效，不自动吊销此前已兑换的普通凭据。
