## 已确认的简化原则

1. 一个仓库是一个知识库，资料一级子目录称为分区，不强制增加 Book/Page 数据库层级。
2. 正式资料是一篇 Markdown 主文档与可选的同名附件目录；附件可包含文档、数据、图片、脚本等。
3. 根 README 说明整个库；分区 README 说明分区用途及与相邻分区的边界。
4. 根 INDEX 和分区 INDEX 由程序自动生成，供人阅读；不由工作 Agent 或复盘模型手写维护。
5. Agent 只维护正文、必要元数据和说明文件。提交前工具生成索引并反馈可修复的问题；不要求 Agent 操作检索数据库。
6. Skill 安装仓库提供的版本，名称为 `组织名-仓库名[-功能]`。共享执行脚本放在仓库根目录 `scripts/`，不复制进每份 Skill。
7. 正文第一个一级标题是显示标题。元数据包含 `summary`、`tags`、`created_at`、`updated_at`，不另存重复的 `title`。
8. Archive 的英文时间戳文件命名和 `archive`、`todo`、`file` 类型只适用于 Archive 仓库，不扩展为所有知识库的统一限制。
9. 集中检索拟统一承担关键词、向量和混合检索；派生索引存放在服务端，不写进资料仓库。
10. 本轮不开发索引工具、Hook、CLI、搜索 API 或模型部署，也不安装本机 Skill。

## 后续组织的职责

- `patchouli-lib`：目标组织名，不代表组织已在本轮创建。
- `archive`：组织内用于归档的知识库仓库；本文的严格文件名规则属于它。
- 其他知识库：各自定义用途、分区、Skill 和写入规则，可以共用检索服务。
- 检索服务代码：以后放独立仓库，名称和部署位置未定。
- 当前开源仓库：保留既有工作和设计记录，不继续为迁就新方案扩建现有业务系统。

组织、仓库重名不表示同一对象。示例 Skill `patchouli-lib-archive` 对应组织 `patchouli-lib` 的 `archive` 仓库，而不是当前仓库的自动改名。
