# 自动索引与提交前检查

INDEX 是供人阅读的生成结果，正式资料仍是 README、主文档及附件。需要保留根 INDEX 与分区 INDEX 以改善 Gitea 网页浏览，但没有 INDEX 不应导致原文无法读取或集中检索无法建库。

本章约定未来工具行为，不在当前仓库新增 Hook、修改 Git 配置或运行资料生成任务。

## 根 INDEX

根 `INDEX.md` 由所有一级资料分区的 `README.md` 自动生成，每行包含：

| 分区 | 用途 | 说明入口 |
| --- | --- | --- |
| 分区名称 | 提取分区 README 的用途段落 | 链接到该分区 README |

只发现符合目录约定的资料分区；排除隐藏目录、工具目录、Skill 目录及符号链接或 junction。缺少 README 的疑似资料分区报告为待修复问题，不静默忽略整批资料。

最终采用“用途摘要加链接回原 README”，不采用早先讨论的全文直接拼接。分区 README 已是一段用途说明，提取不需要调用模型。链接由生成器相对根目录构造，不能直接搬用子文档中的相对链接。

## 分区 INDEX

每个分区 `INDEX.md` 收录该分区直接包含的主文档 `.md`，排除 `README.md` 和 `INDEX.md` 本身，不递归把附件目录中的 Markdown 当作独立主文档。

| 标题 | 摘要 | 标签 |
| --- | --- | --- |
| 第一个一级标题，链接到主文档 | front matter 的 summary | front matter 的 tags |

生成器负责 Markdown 转义、单元格换行处理、相对 URL 编码与稳定排序。长摘要不改写源字段；展示采用安全的一行表格文本，不调用 LLM 压缩。Archive 默认可按文件名时间戳降序展示，同时间以路径排序；其他知识库使用各自明确的排序规则。

## 确定性与维护责任

- 相同资料和配置生成字节相同的 INDEX，不写入每次运行都会变化的“生成时间”。
- 模型不手改 INDEX，也不通过提交一张自己拼的表绕过工具。
- 正式资料新增、删除、移动或修改摘要后，程序更新相应生成结果。
- INDEX 顶部标明自动生成及来源；发现人工改动时提示，不静默丢弃可能属于用户的工作。
- 不为目录索引引入每日复盘 Agent、LLM 摘要任务或另一套人工维护数据。
- 集中搜索从正式资料建立索引，排除生成的 INDEX，避免将同一摘要重复召回。

## 提交前 Hook 与 CI

Git 的机制名称是 `pre-commit`。它可以在创建提交前运行校验，并以非零退出码阻止本次提交，让 Agent 根据诊断修正。它是本地 Hook，不是远端 CI。参见 [Git hooks](https://git-scm.com/docs/githooks#_pre_commit)。

后续可把 Hook 入口保存在仓库受跟踪目录，首次接入时显式启用，例如通过仓库级 `core.hooksPath`。仅 clone 仓库不会自动启用这个本地设置，也不应擅自覆盖用户已有 Hook 配置。参见 [core.hooksPath](https://git-scm.com/docs/git-config#Documentation/git-config.txt-corehooksPath)。

拟议流程：

1. Agent 将本次准备提交的正式资料暂存。
2. Hook 基于暂存区拟提交快照检查并生成所需 INDEX 差异，而不是混用全部未暂存内容。
3. 若 INDEX 需要更新，展示可审阅结果并停止本次提交；Agent 核对后仅暂存对应生成文件，再提交。
4. 若检查失败，输出文件路径、行号、问题及修复提示，不自动改写正文或元数据含义。
5. 检查通过才创建提交。

若生成路径已有未暂存人工改动，先报告冲突，不覆盖。部分暂存时必须保证 INDEX 只反映本次提交的源资料；不得为了方便运行 `git add .` 将其他任务内容一并纳入。

远端 Gitea CI 使用同一检查器复核提交快照和生成结果。它不自动修正文档、不回推生成提交，避免循环触发。Hook 可被跳过，网页编辑也可能不经过本地 Hook；未来是否将 CI 设为受保护分支合入门槛，在启用时配置，不能仅靠本地检查宣称全仓合规。

此流程只需要必要的文本与链接检查，不运行完整产品测试、浏览器矩阵或模型推理。

## 检查范围

| 对象 | 检查 |
| --- | --- |
| Archive 主文档 | ASCII 文件名、固定格式、合法时间戳、已知类型、slug，以及同名附件归属 |
| 主文档元数据 | YAML 可解析，必需字段存在且类型正确，summary 非空，tags 为字符串列表，时间格式合法 |
| 主标题 | 能从正文解析出第一个一级标题，不误读代码块 |
| 相对链接与图片 | 在拟提交快照中能找到目标，正确处理路径编码、片段及引用式链接；不依赖本机绝对路径 |
| 分区 README | 用途清楚；禁止相对链接、相对图片及同类 HTML 引用 |
| INDEX | 与正式资料重新生成结果一致，无重复条目、失效路径或自我收录 |
| 文件集合 | 不通过符号链接或 junction 越出仓库，不把工具、缓存、凭据和生成数据库当成资料 |

链接检查覆盖本库文件和可识别的 Markdown 标题锚点；不能识别的自定义锚点明确提示，不假称已经验证。正文跨目录链接可以存在，按实际相对路径核验；分区 README 的禁止规则单独适用。

外部网络 URL 不在每次提交时强制联网验证，以免站点超时导致资料无法提交。必要时另行检查。删除或移动文件时应检查受影响的反向引用，不能只检查被编辑文件内部的链接。

附件脚本只作为数据处理；检查器不执行文档中嵌入的命令。Archive 主文档规则不应套到 Skill front matter、README、AGENTS、生成 INDEX 或附件 Markdown 上。

## 旧资料与跨平台

现有资料不因这份规范立刻报错或被自动改名。实施前应明确新仓库初始内容和旧数据兼容方案；当前只写设计，不扫描并改写旧归档。

实际工具应使用统一的 Python 实现处理路径、编码和 Markdown，各 shell 只提供薄入口。Windows 和区分大小写的文件系统都应能得到相同的生成结果；大小写碰撞必须报告，不能在一个系统上悄悄合并两个文件。
