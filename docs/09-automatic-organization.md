# 自动整理：可审查的 Book 建议

## 原则

PatchouliLib 可以计算并展示 Book 拆分或合并建议，但默认不会自动执行。用户或获授权
的调用方需要审查所提议的改动。

## 拆分建议

拆分工作流可以分为两个阶段：

1. **确定性初筛**衡量大小、主题多样性、检索混淆度或其他已公布信号。
2. **语义审查**评估候选项，并写出包含 Page 分配方案和置信度、理由充分的提案。

输出是提案，不是内容变更。提案必须标明输入 Revision 集合，并在相关内容变化时
变为过期状态。

## 合并建议

合并初筛比较 Book 之间的相似性以及每个 Book 内部的一致性。准确的距离函数和阈值
仍处于实验阶段。合并提案必须说明命名、Section 归属、Page 移动、Tag 影响，以及
如何保持链接有效。

## 应用决定

被接受的提案使用普通的可审计操作：

- 必要时创建目标 Book；
- 通过改变归属元数据移动 Page；
- 保留 Page ID 和 Revision 历史；
- 使受影响的派生索引失效或更新它们；
- 记录提案、批准者、操作和结果。

拒绝或推迟提案也是一条审计事件。

## 调度与冷却期

一种可行的调度器只评估自上次扫描后发生变化的 Book，并强制两次扫描间的最短间隔。
被拒绝的建议会进入更长的冷却期，避免反复干扰。准确间隔必须可配置，不应成为
API 契约。

## 展示

Book 层查询可以包含紧凑、非阻塞的建议提示。后续界面也可以提供审查队列或时间线。
建议生成不可用时，检索结果仍必须正常使用。

## 安全约束

- 建议不能绕过授权。
- 整理任务绝不重写源文本和 Revision 历史。
- 模型只能接收部署的提供方策略允许的内容。
- 每项建议都要引用促成该建议的 Page 和信号。
- 必须提供确定性方式来忽略、使建议过期并重新生成建议。

## 开放的评估工作

- 拆分与合并质量指标；
- 误报成本和可接受的审查负担；
- 重组期间 Derived Fact 的行为；
- 与提供方无关的语义审查；
- 手动决定与后续扫描之间的相互作用。
