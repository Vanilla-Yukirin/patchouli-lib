# 网页管理面板

> 下文详细步骤以旧密码登录和 operator 凭据流程为基线，不能用于推断新功能已在线
> 可用。开发分支的主 Token 登录、新 Agent Token 再次显示与敏感读取审计已经写入
> 代码，但尚未合并、部署或完成整体验收；两种模式的差别见[开发分支现状](#开发分支现状)。
> 尚待决定的兼容与安全问题见[下一阶段提案](proposals/next-phase-product-and-api.md)。

[简体中文兼容文件](admin-web-console.zh-CN.md)作为既有链接的入口保留；本文件是
规范入口，两份文件的面向读者正文均使用简体中文。

这个可选面板把现有的本地管理员功能放到一个简单网页中。它不是部署控制台，没有
主机、Docker、镜像更新、镜像回滚、备份恢复或 Shell 权限。

## 启用面板

旧密码登录需要同时提供下面两个配置。开发分支只要配置会话签名密钥即可注册
`/admin` 页面；密码校验值仅用于主 Token 尚未初始化时的旧登录。无需配置访问
地址白名单：

- `PATCHOULI_ADMIN_PASSWORD_HASH`：带盐的密码校验值；
- `PATCHOULI_ADMIN_SESSION_SIGNING_SECRET`：单独生成、至少包含 32 个 UTF-8 字节
  的随机值。

旧版本的 `PATCHOULI_ADMIN_ORIGIN` 已移除；即使环境文件还保留它，也不会限制访问。
同一服务可通过多个入口使用，不需要为每个域名或 IP 增加应用配置。各个域名的浏览器
会话分别保存，使用同一个管理密码登录即可，不会自动跨域共享登录状态。

在本机生成密码校验值：

```text
patchouli-admin-password
Administration password:
Confirm administration password:
pbkdf2_sha256$...
```

这个命令不接受命令行参数；在交互式终端中输入密码时不会显示字符。请把输出当作
敏感配置。密码和校验值都不能放进 Shell 参数、受跟踪文件、截图、Issue 或日志。

如果通过 Compose 的 `.env` 文件提供校验值，要用单引号包住完整内容，避免其中的
`$` 分隔符被解释；这个私有 `.env` 文件也不能加入版本控制。

会话签名密钥必须用密码学安全的随机数生成器单独生成。不要复用管理密码、密码
校验值、Agent 凭据、管理员凭据、检索游标签名密钥或 TLS 私钥。可选的
`PATCHOULI_ADMIN_SESSION_TTL_SECONDS` 允许 300 到 86400 秒，默认是 1800 秒。

两个配置全部为空时面板保持关闭；只设置会话签名密钥时，开发分支允许启动。
只设置旧密码校验值而没有会话签名密钥时，应用会拒绝启动。
会话 Cookie 默认设置 Secure，适用于浏览器通过 HTTPS 访问。普通 HTTP 入口需要
下面的明确开关，否则浏览器不能通过 HTTP 携带登录 Cookie。

## 开发分支的网页首次设置主 Token

此功能已在开发分支实现，未合并或部署；它建立单人管理身份，不创建知识库或
Agent，不改变现有 Agent／operator 凭据。需要当前数据库结构和独立会话签名密钥。
不需要新增数据库迁移，主 Token 仍只保存不可逆校验值。

已有旧密码的安装：先通过 `/admin/login` 登录，在“初始化与凭据”中点击“首次设置
主 Token”，或打开 `/admin/master/setup`。有效旧会话与 CSRF 就是设置授权，不需再
填写 operator Token 或一次性设置凭据。设置成功立即切换到主会话；旧密码和旧 v1
Cookie 不再能登录。旧 `/admin/setup` 仍是登录后的结构与凭据页面，不被此入口覆盖。

没有旧密码的新安装：部署者在私有环境中配置 `PATCHOULI_ADMIN_SETUP_TOKEN`，
使用单独生成的 32 至 1024 UTF-8 字节随机值；不能与会话签名密钥相同，也不能在
缺少会话签名密钥时启用。打开登录页会转到首次设置页，输入这份一次性设置凭据、
新的主 Token 并确认。设置凭据不是新的主 Token，不发送给模型，也不放进 URL、
命令参数、公开配置、日志或截图。设置成功后，应从私有环境文件移除此设置凭据。

没有设置凭据且没有旧登录会话时，网页设置关闭：仅“数据库为空”不会授权注册，
也不通过 IP、私网地址或代理头判断设置权限。本机 CLI 首次设置仍可使用。主身份一旦
存在，网页设置不能再次覆盖；轮换与遗失恢复继续使用已有的本机流程。

首次设置表单使用独立的 5 分钟限定用途 Cookie 和匹配 CSRF，不能作为普通管理
会话；它不含设置凭据或主 Token。提交还检查当前同源。在同一个写事务内重新核实
Cookie、授权、数据库结构及主身份仍为空，创建身份和脱敏 `auth.master.initialize`
审计；并发请求只允许一个成功，审计写入失败则身份也回滚。输入不一致、长度不符
或重复字段拒绝并不回显密钥。Token 可由密码管理器生成、保存和填写，服务自身不把
它写入浏览器持久存储。HTTPS 和明确开启的加密私网 HTTP 使用相同授权流程。

## 开发分支的历史文件组恢复

主 Token 登录后，打开任意 Page 的历史版本预览，点击“恢复此版本”。确认页展示
所选版本编号与文件清单；核对后勾选确认并提交。提交时服务才核验完整文件字节和
摘要，不将清单展示当作完整性验证。单 Markdown、多文件和纯二进制使用同一流程。

恢复只改变当前整组文件。内容不同则追加一个新 Revision；旧版本始终保留。内容
完全相同则不新增版本或内容活动。Page ID、标题、Tag、声明时间和知识库／分区／
书籍归属不变；这不是恢复数据库备份，也不是把已删除 Page 移出回收站。
真正的变化沿用“修订”活动与准确版本链接，Source 另行记录选中的历史 Revision。

恢复表单要求主会话、同源、CSRF、当前强 ETag 和明确确认。新操作在页面已更新或
删除时拒绝，不覆盖并发更改。同一标签页会话存储仅保存原操作键、准确目标路径和
原 ETag，不保存 Token、Cookie、CSRF 或文件内容。结果未知时可刷新并重试；不能
换用新 ETag 或源版本冒充原操作。需另做操作时，先检查上次结果，再明确放弃重试
并重新读取当前状态。无法保存重试记录时不发送请求。

原成功操作在后续修订或删除后仍可返回准确旧回执，不再增加版本，也不会恢复已
删除文档。此时成功链接可能无法打开（页面仍在回收站），并不表示恢复失败；回执
不承诺是当前版本。新操作则必须重新读取当前状态。没有可重试记录的不可用页面
不会开放新操作。

恢复功能本身复用 `0026` 文件集回执，不新增迁移。开发分支的 `0028` 移动历史使
主会话原成功可在文档移动后按旧请求重放；旧回执的原路径字段不改写，不能视为当前
位置。备份证明成功结果，不独立证明用户当时所选源版本；当前不提供 Agent 专用
恢复 API。接口仍为开发切片，未合并、部署或完成整体成品验收。

## 开发分支的文档移动

主 Token 登录后，在文档当前版本页点击“移动文档”，选择同一知识库中的目标分区
和书籍，勾选确认后提交。不需要重新上传文件；Page ID、文件、全部历史、标题、Tag
和声明时间不变。移动只调整归属并记录近况，不增加内容版本。选择原位置会提示
“未移动”，也会保存这次成功，防止以后重试产生意外移动。

表单保留当前标签页的原路径、目标、版本条件及操作键；网络断开、刷新后可原样
重试。结果不确定时目标选择锁定，先核对结果再明确放弃原重试。服务端原成功在后来
更新、移动或删除后仍可返回，不会再次移动或将文档移出回收站；提示会说明该结果
可能不是当前位置。页面提供按稳定 Page ID 查看当前文档与准确版本的链接。

仅主会话可使用此网页入口；不跨知识库、不移动已删除文档，也不移动整个分区或
书籍。新操作仍检查登录、同源、CSRF 和版本条件。定向测试已覆盖普通 HTTP 下的
断响应恢复及备份往返；整树与运行环境验收仍需另行记录。

## 多入口与同源提交

登录页和样式不再检查预设的 Host。登录、退出和管理表单仍要求浏览器提供 Origin，
且它的协议、主机名和端口必须与**当前请求**一致；不接受缺失、重复或格式含糊的值。
这项自动检查无需维护白名单，用于防止其他网站借用浏览器会话提交管理操作。
管理操作还要求有效签名会话和匹配的 CSRF 值。所有跳转保持站内相对路径。

HTTPS 入口代理须保留浏览器的原始 Host（包括非默认端口），并覆盖传入的
`X-Forwarded-Proto` 为实际协议。应用使用 ASGI 服务解析后的协议，不直接信任任意
转发头，也不使用 `X-Forwarded-Host` 替换 Host。

使用 Uvicorn 时，只在其 `FORWARDED_ALLOW_IPS` 中信任实际直接连接的代理地址。
公开 Compose 文件会把私有环境中的该值传入容器，默认只信任 `127.0.0.1`。
代理与 API 之间若经过容器网桥，该地址可能不是回环地址，须按实际连接设置；不要
无条件设为 `*`。这是代理身份的配置，不是浏览器域名白名单。代理协议没有正确传入
时，页面可能可见，但登录仍会因协议不一致被拒绝。

## 仅在加密私网中使用 HTTP

如果所有访问都通过管理员控制的加密私网（例如 Tailscale），可以不配置域名和 TLS
证书。在私有配置中设置 `PATCHOULI_ADMIN_ALLOW_PRIVATE_HTTP=true` 即可。

该选项默认关闭；它只影响 HTTP Cookie 的 Secure 属性，不再检查预设 IP，也不是
网络访问控制。管理员须确认流量确实走加密私网。代理只绑定选定的私网接口地址，
不要绑定 `0.0.0.0` 或 `[::]`；
API 仍只绑定回环地址。HTTP 代理需转发原始 Host，设置 `X-Forwarded-Proto http`，
保留登录限速和请求体上限。浏览器和客户端须将该私网地址排除在外部代理之外。

密码校验、短期会话签名、HttpOnly、SameSite=Strict、自动同源检查、CSRF 和 API
Token 权限检查全部保留。仅 HTTP 会话不设置浏览器无法用于 HTTP 的 Secure 标记；
HTTPS 会话仍设置它。浏览器可能显示“非安全”，但不再发生证书信任错误。

这不是给现有公网入口关闭 TLS 的方法。公开的 TLS 示例保持不变，真实监听地址和网络
配置不写入仓库。Agent 的 Python、CLI 和 MCP 配置见[客户端说明](../clients/python/README.md)。

## 在前面放置 TLS 入口

公开的 Compose 服务仍然只监听本机回环地址。把
`deploy/nginx/patchouli-admin.conf.example` 复制到管理员自己的私有配置，替换
示例服务器名称与证书位置，并在重新加载前验证 Nginx 配置。

这个 Nginx 示例会：

- 负责 TLS，并把原始 Host 转发给 FastAPI；
- 限制登录端点的请求频率；
- 把管理表单请求体限制为 16 KiB；
- 单独保留 Archive 接口所需的请求体上限；
- 只转发到本机回环 API，不在公开仓库记录真实目标地址或证书位置。

其他入口代理也可以使用，不要求 Nginx；须保留上述协议传递、登录限速及监听边界。
虚拟组网或隧道不会自动提供额外身份认证。不要为了绕过 TLS 和登录限速边界而把回环
API 直接暴露到不可信网络。本次入口改动不修改已有代理或网络配置。

## 使用面板

旧模式访问 `/admin/login` 并输入管理密码。旧版短期会话 Cookie 包含到期时间和
随机 CSRF 值；开发分支的主 Token 会话还包含管理身份、会话代次和模式，均不
包含 Token 明文。
登录后 `/admin` 是内容近况首页；首次设置、管理员凭据恢复和现有 Agent 凭据操作
集中在左侧“初始化与凭据”(`/admin/setup`) 页面。知识库和身份分别在各自的导航页。

右上角的 `中文 / English` 控件可以切换整个面板，包括表单校验和错误提示。语言选择
保存在另一个非敏感的 HttpOnly、SameSite=Strict Cookie 中；它仅限 `/admin` 路径，
只包含 `zh-CN` 或 `en`，退出登录后仍会保留。它既不是管理会话，也不会包含或替代
任何 bearer 凭据。一次性凭据结果页会有意隐藏语言切换，避免用户因切换语言而丢失
唯一显示的一份凭据。

第一版可以完成：

1. 一次性创建 Library、Section、Book 和第一个本地管理员；
2. 恢复管理员凭据，同时吊销此前仍有效的管理员凭据；
3. 为一个明确的 Section 创建 Agent、精确权限和一份凭据；
4. 吊销指定的 Agent 凭据；
5. 查看只读的管理员、Agent 和 MCP 使用说明。`/admin/agent` 链接到公开的
   `/connect` 接入页，可复制不含凭据的 AI 原生指令。设备 Token 必须由使用者在
   本机交互式输入；Agent 可在鉴权后获取 `/api/v1/agent/skill/manifest` 及清单中
   的 Skill 文件，并核对 SHA-256。标准 HTTP 不依赖专用 CLI/MCP；指南列出统一
   文件集与当前 Page 搜索入口，搜索需要就绪的索引。
   `/admin/guide` 还展示经过审核的固定 API 目录及明确标为合成、非实时的 JSON
   响应；`/admin/agent` 只读展示打包 Skill 的版本、摘要清单和文件正文；`/admin/mcp`
   展示当前工具名及合成返回格式。页面不调用内容 API，也不把管理会话 Cookie 当作
   Bearer 凭据。旧 `section_search` 已退役；当前搜索入口为受 Bearer 保护的
   `POST /api/v1/search`，索引未就绪时返回 `search_unavailable`。
6. 登录后逐层浏览已有知识库、分区、书籍和未删除 Page，查看当前及历史 Revision 的
   Markdown 正文安全转义文本、准确文件名、字节数与 SHA-256；已软删 Page 在此不可
   访问。在层级浏览页可分别新建知识库、分区和书籍；已有名称冲突会提示，不会覆盖
   旧内容。此处尚无多文件预览、版本恢复或 Page 编辑。
7. 旧版首页只读显示最近的成功 Archive 创建、修订、发生时间更正、删除、恢复，
   以及 Tag 创建、页面关联和解除关联活动。可进入对应身份详情；可访问的 Page 进入
   预览或准确 Revision，当前已删除的 Page 进入受保护的回收站。标题和标签名取当前
   状态，不表示操作时的历史名称；若资源已不可访问则显示安全的纯文本。时间悬停
   显示完整 UTC 时间。普通 API 请求和失败请求不作为内容活动。开发分支将活动
   改为每页 20 条并可继续翻看，还增加仅主会话可见的独立 API 请求记录页。
8. `/admin/agents` 提供受管理会话保护的身份清单，展示所属知识库、身份类型、状态和
   创建时间，并可进入身份详情。身份详情只读展示现有凭据的 ID、有效／尚未生效／
   到期／撤销／轮转状态、创建、到期、最后使用、撤销和轮转时间，以及所属知识库中的
   当前 Section 授权（分区名称、ID 和精确操作）。已停用身份的未撤销凭据标为不可用。页面不会
   查询或显示凭据选择器、校验值或原始 Token；现有 Token 无法从校验值恢复或再次
   复制。这仍是旧的单知识库＋分区授权，不代表跨知识库权限已经实现；完整 Token
   管理仍属于下一阶段提案。
9. 知识库内可浏览 Tag 及其未删除 Page；Page 预览可查看、关联或移除 Tag，也可新建
   Tag。每次 Tag 写入均须在表单中另填**该知识库的有效管理员 bearer Token**；网页登录
   Cookie 只负责会话、同源及 CSRF 检查，不会代替内容授权。Token 不预填，也不保存到
   会话或结果页。重复关联或移除会明确提示未发生变化；此处的分库 Tag 浏览
   不等于跨知识库授权。
10. 登录后可从知识库或分区进入回收站。列表仅显示已删除 Page 的标题、所属
    分区／书籍和删除时间；详情还显示 Page ID、类型、声明发生时间及当前版本号。
    列表按删除时间由新到旧、同一时间按稳定 Page ID 排列，每页最多 20 条，可继续翻页。
    正文、历史文件和原始凭据不会在回收站读取；未删除、已恢复、跨库或跨分区的
    Page 详情一律返回 404。Archive 类型的详情提供恢复按钮：每次提交须输入该
    知识库有效的管理员 bearer Token，网页会话仍须通过同源及 CSRF 检查。恢复使用
    当前 Page ETag 保护并发更新，并以同一表单的幂等键处理重试；成功后保留原 Page ID
    和全部历史版本，跳转回所属分区。Token 不预填、不写入 Cookie 或结果页面。
    非 Archive 类型当前不提供网页恢复。

开发分支另有 `/admin/search` 人类搜索页，仅主 Token 会话可用。它通过带同源与
CSRF 校验的 POST 表单提交关键词、可选知识库、Tag 任一匹配及 UTC 声明时间范围，
不会把搜索词或续页游标放进 URL；结果中的纯文本摘录安全转义，并可用保留原筛选的
POST 表单继续翻页，点击结果进入当前 Page 的安全预览。摘录取自规范化索引文本，
不是原始文件字节；查询、授权或可见结果变化使游标失效时，应重新发起首页搜索。
网页搜索与 Agent 使用相同的索引和可观察查询语义，但网页会话不会变成 Agent
bearer Token。索引未就绪时会明确返回不可用提示；本分支尚未合并、部署或完成
整体容量验收。

网页登录后新建知识库、分区或书籍无需另填管理员 bearer 凭据。这三种操作会在
同一数据库事务内写入结构和独立的网页会话审计记录；审计仅存随机会话标识的
不可逆指纹，不存管理密码、Cookie、CSRF 原值或 bearer Token，也不会冒充
`auth_audit_events` 中由 bearer 凭据认证的调用方。新建结构不自动给已有 Agent
扩权，也不自动创建管理员或 Page。若要为新知识库签发 Agent 凭据，仍须走现有
管理员凭据流程；更细的跨知识库权限管理尚未实现。

“首次设置”会创建保存 Page 前必须具备的最小内容结构：

- **知识库（Library）** 是整个知识空间。个人使用通常一个就够了；需要分开管理和
  授权时可以创建多个，但同一次部署中的知识库仍共享服务和数据库，并不是物理上
  完全分开的系统。
- **分区（Section）** 是长期使用的大分类，也是给 Agent 划定权限的范围。
- **书籍（Book）** 是一个分区内更小的内容集合。每个 Page 只属于一本书。

分区说明和书籍摘要都是可选的文字说明。管理员名称用于标识管理员，审计记录会关联
到这个身份；它不是网页登录账号。“管理员令牌有效期”只决定首次生成的管理员
bearer 令牌多久过期，不会让 Library 或网页管理密码失效；默认 `3600` 秒即一小时。

操作表单中的管理员凭据只用于当前请求。现行旧流程的新管理员或 Agent 凭据只会在
禁止缓存的结果页面显示一次。离开页面前，应记录 Library、caller 和 credential ID。
旧凭据只存校验值，丢失响应后无法还原；开发分支新签发的 Agent Token 另存于
SQLite，并已由受同源、CSRF、凭据状态与审计保护的主 Token 会话 POST 操作单独
显示。主 Token 本身只存不可逆校验值，不会因此改为明文保存。

面板不会把 bearer 值写入 Cookie 或其他浏览器存储。不要安装会捕获表单内容或页面
机密的浏览器扩展，也不要添加记录请求体或响应体的中间件。

## 开发分支现状

主 Token 不由网页自动生成。先完成数据库迁移，再由有权访问该数据库的操作者在
本机交互式执行 `patchouli-master-token initialize`，输入并确认自行生成的长随机
Token。执行前核对命令读取的 `PATCHOULI_DATABASE_URL` 或当前目录的 `.env` 指向
**与服务相同且已迁移到当前结构**的 SQLite 数据库，避免误初始化另一份数据库。
`rotate` 还要求当前主 Token。命令不把 Token 作为参数或打印出来。

开发分支提供以下本机命令；它们不是网页或公开 HTTP 接口：

```text
patchouli-master-token initialize
patchouli-master-token rotate
patchouli-master-token recover --confirm-local-reset
```

`initialize` 仅在主身份尚未设置时创建。`rotate` 要依次输入旧 Token、新 Token、
再次确认新 Token。忘记旧 Token 时，拥有数据库本机访问权限的操作者可使用
`recover --confirm-local-reset`，仅输入并确认新 Token。输入过程不显示字符；新 Token
不能与当前值相同。恢复不创建缺失的主身份，也不改变其身份 ID 或 Agent／operator
凭据，但会立即使旧主 Token 和已有管理会话失效，须用新值重新登录。

自动化输入可在命令末尾明确加上 `--stdin`：首次设置或遗失恢复读取两行相同的新
Token，轮换读取旧值、新值、再次确认新值三行，随后须结束标准输入。不要把这些值
写成命令行参数、Shell 历史、受跟踪文件或日志。命令只改变正在连接的数据库，不会
寻找其他副本；同样不能阻止日后恢复更早的数据库备份把主 Token 状态回退。
上述遗失恢复已经加入开发分支，尚未合并或部署；网页不提供免鉴权恢复入口。

主 Token 初始化后，网页登录只接受主 Token，旧密码和旧 v1 会话均被拒绝；
轮换或本机恢复后旧主会话失效。这不会自动吊销旧 operator Bearer 凭据，也不表示旧 API
都已删除。主会话已能签发、轮换、吊销新 Agent Token、编辑逐 Library 读写授权，
以及执行部分内容管理、Tag 与回收站操作；不需要在这些主会话表单再填 operator
Token。旧 `/admin/setup` 的初始化等操作仍属旧流程，主会话不能直接使用。

主会话在当前 Page 预览中可勾选确认后“移入回收站”。这是整个 Page 的软删除：
所有版本、同层文件及关联记录都保留；已删除 Page 不出现在普通浏览或搜索中，
但可以从回收站恢复同一个 Page。历史版本预览不提供删除按钮。表单核对当前
Page ETag，页面打开后若有其他更改，会要求重新加载；重复提交不新增删除记录。
删除与恢复都复核主会话代次，并与脱敏审计、搜索索引维护一并成功或回滚。
首页的删除活动链接到回收站详情。

此功能需要开发分支的 `0025` 数据库迁移。迁移保留旧 Caller 和主会话恢复历史；
一旦产生主身份删除记录，就拒绝降级到无法表达它的 `0024`，即使后来已经恢复
页面也不删除历史审计。旧 `0024` 备份仍可通过显式 `--schema-revision 20260930_0024`
按原格式校验和恢复，不会自动升级。上述能力已实现并通过合成测试，尚未合并或部署。

开发分支的 Page 当前／历史预览文件清单新增原始文件下载链接。链接固定到当前
正在查看的版本编号，后续上传不会使旧链接改为下载新版本。下载使用现有登录
Cookie，无需再输入 Agent Token；主 Token 会话必须仍为数据库中的当前代次，
旧密码 Cookie 只在主身份尚未创建时兼容。

会话、完整 Library／Section／Book／Page 归属、未删除状态和精确版本，在同一个
SQLite 读取快照内核对。返回文件前验证整个版本的封印、文件数量、字节和摘要；
另一文件损坏也不会退化为部分下载。不存在的路径、文件或版本返回 404，校验失败
返回脱敏 500。文件以 `application/octet-stream` 附件返回，禁止缓存和 MIME
猜测，不在浏览器中内联执行。此下载不使用本机文件路径，也不提供回收站正文。
这仍是开发分支能力，尚未合并或部署；网页上传、整组修订及指定历史版本的完整
文件组恢复均已在开发分支接通。历史恢复保留原版本，并按内容差异决定是否新增版本。

### 开发分支的网页上传与更新

以下流程需当前开发分支和 `0026` 数据库结构，不代表既有部署已更新：

1. 使用主 Token 登录，进入“知识库”，依次进入分区和书籍。
2. 点击“新建文档”，填写标题、可选的声明时间，选择本版本的全部文件，再点“保存文件”。
   声明时间采用明确时区的 RFC 3339 格式，例如 `2026-01-01T12:00:00Z`；不填会使用
   服务器接收时间并提示。非法时间拒绝提交，不会静默改成当前时间。
3. 查看成功结果中的准确版本链接。单份 Markdown、多文件和纯二进制都走同一流程；
   原始文件只安全下载，不在网页中执行。
4. 更新现有文档时，从**当前**版本预览点击“更新文件”，重新选择新版本的全部文件。
   新版本整组替换，遗漏文件仍保留在旧版本中；完整文件组相同则提示不新增版本。
   历史版本不提供此按钮，更新不改变 Page ID。

创建成功后，明确点击“开始新操作”可继续创建另一份文档；不会沿用刚才的操作键。
更新成功后，点击“重新读取当前版本，继续更新”取得新的版本标识，再提交下一次修改，
不能继续使用旧表单自动覆盖。

数量和大小继续使用现有文件集限制：最多 64 个同层文件、单文件 16 MiB、整组
64 MiB；不接受子文件夹和不安全文件名。前置代理如另设较小请求体上限，也会拒绝
上传；旧的 16 KiB 管理表单代理示例不能直接承载此上传，须为上述新上传路由单独
配置合适上限，而不是无条件放大登录或其他表单。网页上传不改变任何网络配置。

断网或响应丢失时，先保留原文件，再重试原操作。本标签页仅保存操作键、目标、
元数据、旧 ETag 及文件名称／大小，不保存文件字节或任何凭据。刷新后需重新选择
原文件；服务器会核对每个字节，不能用同名同大小的不同内容冒充重试。改标题、时间
或文件时点“放弃原重试，开始新操作”，先检查上次是否已经成功，避免另建重复文档。
关闭标签页或清除站点数据不保证还能自动找回原键。浏览器禁止会话存储或禁用脚本时，
上传会明确停用，不把输入内容提交到 URL。

成功重试可能链接一个较早版本，不会覆盖当前版本；Page 后来已删除时返回原成功
结果也不会恢复 Page，其原版本预览仍会返回 404。当前目标不可新写时，更新页保留
带鉴权的 404 重试壳，仅供本标签页已有的原操作重试。新请求仍受有效主会话、同源、
CSRF、整组输入校验及旧 ETag 冲突保护。

首页的内容活动显示实际创建和修订的准确版本，后来更名时展示当前标题，已删除时
链接回收站；重复上传和回执重放不追加活动。操作键、CSRF 与正文不写入内容动态。
网页首次创建主身份、指定版本的完整文件组恢复和主会话 Page 移动均已在开发分支
接通。上述能力尚未合并或部署，完整运行环境验收另行记录。

### 开发分支的发生时间修改

使用 `0027` 或后续结构的开发分支，主 Token 登录后，可在文档**当前版本**预览
中的“修改文档发生时间”填写带时区的时间，例如 `2026-08-13T10:00:00Z`，再点击
“保存发生时间”。该日期用于搜索筛选和书籍中的文档排序，不是服务器上传日期。
文件、页面 ID 和全部历史版本保持不变；近况会显示实际更正活动。

时间必填：格式错误或取值无效会拒绝；同一个时间不产生新记录。如果打开表单后
页面被修改，旧版本条件会被拒绝，应重新载入当前页面再改，不能覆盖他人的新操作。
回收站或历史版本页不能修改发生时间。时间、审计及已就绪索引在同一事务更新；
失败时整体回滚。该功能尚未合并或部署。

校正不会改写以前的上传成功回执；原操作重试仍返回当时的结果，并不会将当前
声明时间退回。备份兼容细节见[下一阶段时间方案](proposals/next-phase-product-and-api.md)。

开发分支的 `/admin/requests` 独立展示 API 请求元数据，与首页成功内容活动分开；
在线记录默认保留 30 天，不含 Token、正文、搜索词或原始查询串。代理侧拒绝或
数据库不可写时可能没有对应记录。主会话的 `/admin/search` 已可用，但索引未就绪
时会明确报不可用；搜索摘录与 POST 续页已在开发分支接入，目标容量性能验收尚未
完成。这些功能均不能因为已经写入分支而称为已合并或已部署。

旧管理面板的[决定记录](decisions/0003-admin-web-console.md)仍是历史设计决定，
未被本页自动修订。主 Token 的网页首次设置、旧网页登录与 operator 流程的退出安排、
敏感 Token 再次显示是否要求近期重新验证，以及含 Agent Token 明文的 SQLite、
WAL 和备份如何保管，仍须产品／安全审查。恢复旧备份会恢复到备份时的凭据状态，
包括当时尚未吊销的 Token；不能在未核对备份与恢复后果前对有数据的服务启用迁移。
