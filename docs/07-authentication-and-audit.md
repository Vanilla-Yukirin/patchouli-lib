# 身份验证、授权与审计

> 本文记录现行旧凭据「只显示一次、按 Section 授权」的基线。开发分支已加入
> 新 Agent Token 的 SQLite 明文存储及逐 Library 授权，但尚未合并或部署，
> 敏感读取审计和完整跨库写入仍未完成。不能将目标理解为旧凭据已经可还原。
> 后续边界见[提案](proposals/next-phase-product-and-api.md)。

## 凭据类别

本设计区分：

- 用于凭据管理、策略变更、导出和例外擦除的管理凭据；
- 供 CLI 工具、MCP 客户端、服务和 Agent 使用的有作用域调用方凭据。

管理凭据不得用于普通读写。调用方凭据需要名称和说明以便审计，但示例必须使用
合成身份。

已认证的 `/api/v1/auth/whoami` 返回调用方名称、说明、身份与凭据标识、到期时间和
当前 Section 授权；不返回原始 Token、选择器或校验材料。名称与说明只供调用方确认
自己持有的是哪份身份，不替代实际授权检查。跨 Library 的读／写权限尚未上线。

## 凭据处理

凭据处理须按类型区分：

- 公网入口通过 HTTPS 接受凭据；仅在明确配置的受保护私网入口允许 HTTP；
- 主 Token 只存不可逆校验值；新签发的 Agent Token 为可再次显示而在 SQLite
  单独保存明文，数据库、WAL 和备份均须按机密材料管理；旧凭据不能从校验值还原；
- 普通列表和详情不加载明文；再次显示新 Agent Token 必须有主会话、同源与 CSRF
  校验，并记录不含机密的敏感读取审计；
- 支持到期、轮换、吊销和最后使用时间元数据；
- 避免记录原始授权头或机密；
- 在适用场景使用常量时间校验。

## 授权作用域

Section 和 Tag 约束是候选策略维度。在具体使用场景证明额外复杂性合理之前，Book
和 Page 层规则有意推迟。

建议的基线是新调用方凭据默认拒绝：明确分配作用域前不能访问任何内容。准确的允许/
拒绝优先级，以及无标签内容的行为，仍是开放设计问题。

检索、摘要生成、派生事实访问、引用遍历和整理建议都必须先进行授权评估。只过滤
最终响应远远不够。

## 审计事件

每次被接受的变更都应记录：

- 操作者身份和凭据标识符；
- 操作和受影响资源；
- 请求或关联标识符；
- 时间戳和结果；
- 适用时记录之前和之后的 Revision 或策略版本。

审计数据不得包含原始凭据或完整私有文档正文。保留、导出和完整性保证需要专门提案。

## 威胁模型主题

- 调用方凭据或管理凭据被盗；
- 已存内容中的提示词注入；
- 检索期间发生跨 Section 数据泄漏；
- 摘要生成期间未经授权调用提供方；
- 恶意 Markdown 或引用展开；
- 通过昂贵搜索、上传或模型请求实施拒绝服务；
- 备份泄漏和不完整的管理性擦除。
