# 主会话网页历史文件组恢复

- 状态：提案中（Proposed）。恢复旧内容形成新 Revision、相同内容不新增版本的
  产品目标已确认；本文件描述开发切片，不确立新的稳定 HTTP 契约。
- 范围：单人主 Token 会话选择同一 Page 的某个历史版本，将完整文件组恢复为
  当前内容；不恢复整个数据库，不移动 Page，不永久删除文件或改写历史。

## 用户可见结果

在历史版本预览中选择“恢复此版本”，明确确认，并提交当前 Page 的强 ETag 与
本次操作键。服务读取并验证所选版本的全部同层文件，不要求浏览器下载后重新上传。
单 Markdown、混合文件与纯二进制使用同一逻辑。

若选中内容与当前整组文件相同，返回“内容未变化”，不创建 Revision、Source 或
内容审计。若不同，追加一个内容与所选快照相同的新 Revision；此前的所有版本
仍保留。Page ID、标题、Tag、声明发生时间和归属保持不变。

本切片复用已有 `revise` 成功回执和内容审计。近况仍显示“修订”，不是独立的
“恢复”事件类型；新 Source 的 `kind=revision_restore` 和准确源 Revision ID
用于记录变化操作的来源。是否增加独立活动类型仍可另行决定。

## 复用边界与事务

使用独立短读取快照，先核对主会话及数据库代次、完整 Book／Page 归属，再按
同一 Page 的准确版本编号取得 Revision，验证封印、清单、每个文件字节与摘要。
读取与授权处于同一显式 SQLite 事务，不能用无鉴权的快照读取代替授权。

读取结束后，把准确文件组及确定的来源构造为已有文件集修订命令，交给
`MasterFileSetService.revise_page`。写事务再次核对主身份代次，优先查原成功回执，
无回执时才检查未删除状态和当前强 ETag。内容、Source、脱敏审计及成功回执
继续同事务写入，搜索索引使用已有提交前维护机制。不在外层写事务中嵌套
另一份自行提交的修订服务。

不可变 Revision 允许先短读、后写入。期间发生并发修订、标题／时间修改、软删除
或会话轮换时，新操作由写事务中的版本条件或鉴权复核拒绝，不覆盖更新。
源读取不能预先要求当前 ETag 匹配或页面未删除：否则原成功操作在后续修改或
删除后无法按原键重放。源读取仍须核对身份、Page 和完整路径。

原操作键应保留到得到明确结果；重试使用同一源版本、路径及原 ETag。已有请求
指纹包含来源、目标、旧 ETag 和整组字节，同键改变源版本会冲突。重放返回原成功
结果，不再次追加版本、产生内容活动或把已删除 Page 恢复出回收站。

## 备份与兼容

此方向复用 `0026` 回执及当前 `0027` 数据结构，不需要新增迁移。备份继续验证
原成功的准确结果快照、历史 ETag、Source 关联及主审计。

现有离线验证不独立证明“用户当时选择了哪个源版本”，尤其内容未变化时没有
Source 行；原请求重放才会核对包含所选源的指纹。本切片不增加额外的离线意图
证明要求，也不把结果快照验证描述为已证明原请求输入。

Page 移动尚未实现。当前成功回执仍要求原 Section／Book 归属；未来移动需先
解决历史路径证明，不能声称本片已支持移动后的旧操作重放。
Agent 端专用恢复接口或普通修订请求的选择仍是开放问题，本片仅接通管理网页。

## 验证清单

- 旧 Markdown、混合文件与纯二进制恢复准确；完全相同内容不新增版本。
- 同键准确重放、同键不同源冲突、旧 ETag 新操作拒绝。
- 后续修订、标题／声明时间校正或软删除后，原成功回执保持准确。
- 旧会话拒绝、读写间并发更新及轮换拒绝、错误归属与损坏快照失败关闭。
- 内容、Source、审计、回执及搜索维护失败整体回滚。
- `0027` 备份验证与合成恢复；不以旧结构测试替代实际新数据验证。
- 网页同源、CSRF、明确确认、准确版本链接及原生浏览器操作。

本文件不授权既有部署更新、真实数据迁移或更改其他提案状态。
