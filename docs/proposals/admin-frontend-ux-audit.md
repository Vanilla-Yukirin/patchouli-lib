# 管理前端现状问题

- 状态：提案中（Proposed）；本文记录审查时的代码现状，作为
  [整改总览](admin-frontend-rebuild.md)的依据
- 范围：`src/patchouli_lib/admin/` 下的页面渲染、路由与内嵌脚本

## 已有的优点

整改时应保留以下做法：

- 严格的安全响应头：CSP `default-src 'none'`、`frame-ancestors 'none'`、
  `Cache-Control: no-store` 等（`router.py` 的 `_SECURITY_HEADERS`）；
- 所有写操作带 CSRF 值和同源检查，Token 只出现在密码输入框或一次性结果页；
- 基础无障碍：表单均有 `label`，列表与导航有 `aria-label` / `aria-current`，
  复选框适配强制颜色模式（forced-colors）；
- 乐观并发：编辑表单携带 `expected_updated_at` 或 `expected_etag`，过期时拒绝。

## 一、工程结构

- 页面以 f-string 拼接 HTML：`pages.py` 约 3700 行，另有 `file_set_pages.py`、
  `page_move_pages.py`、`revision_restore_pages.py`、`onboarding_pages.py` 等。
  没有模板、组件或类型检查，相同结构反复手写。
- 样式是 `pages.py` 中的 `STYLESHEET` 字符串；脚本是 `REVEAL_SCRIPT`、
  `TAG_MANAGEMENT_SCRIPT`、`FILE_SET_UPLOAD_SCRIPT`、`PAGE_MOVE_SCRIPT` 等
  Python 字符串，由路由以 `/admin/*.js` 输出。修改任何界面都要改 Python 并重启。
- 单个页面函数承担过多职责，例如 `page_preview_page` 同时生成历史、文件、标题
  表单、时间表单、回收站和标签管理六块界面。
- 现有 `tests/admin/test_*_browser.py` 通过测试客户端断言 HTML 片段，与具体
  标记结构耦合，重构时需要整体改写。

## 二、多语言

同时存在三套机制：

1. `_ZH_CN` 字典，以英文原文为键，约 270 条；
2. `_CREDENTIAL_LABELS` 在显示时把 “Agent” 一类旧键改称为 “凭据”，界面文字与
   代码中的键不一致；
3. 约 46 处内联的 `"中文" if locale == "zh-CN" else "English"` 写法。

默认语言固定为英文（`router.py` 的 `locale_for`），不读取浏览器的
`Accept-Language`。

## 三、信息架构与导航

- 顶部导航（`_header`）与左侧栏（`_sidebar`）重复列出知识库、搜索、身份、指南、
  Agent、MCP。
- 侧栏 10 项把日常操作（知识库、搜索、标签、回收站）与开发者接入说明（指南、
  Agent、MCP）平铺在一起，没有分组。
- “API 请求” 只在当前页面就是该页时才插入侧栏，平时只能从首页底部链接进入。
- 首页只有内容活动时间线，没有概览、统计、快捷入口或待处理事项。
- 内容只能逐层点击进入（知识库 → 分区 → 书籍 → 页面），没有目录树；列表只有
  基于游标的 “下一页”，没有上一页、排序或筛选。

## 四、操作与反馈

- 多数写操作仍在表单提交后整页重新渲染或重定向，页面滚回顶部；小票已有同页
  抽屉，文件上传、移动与版本恢复也已有局部请求，但整体操作尚未统一。
- 全站缺少一致的行内校验、加载状态、Toast 或撤销入口；错误提示与普通提示都使用
  `role="status"`（`_notice`）。
- 页面详情中所有低频操作表单（改标题、改发生时间、移入回收站、管理标签）始终
  完整展开，主要操作（更新文件、移动、恢复版本）是并列的链接按钮，缺少主次。
- 危险操作样式不一致：“移入回收站” 使用普通主按钮，需要先勾选确认框；标签批量
  删除使用 `.danger` 样式。

## 五、时间

- 所有时间以 `YYYY-MM-DD HH:MM UTC` 显示（`_time`），不按浏览器时区呈现；相对
  时间（`_relative_time`）仅在悬停提示中给出 UTC 绝对时间。
- 发生时间输入框要求手写带时区的 RFC3339 文本（如 `2026-01-01T12:00:00Z`），
  没有日期时间选择器，也不提示与本地时间的对应关系。

## 六、内部概念暴露

- 上传页要求用户理解 “操作键”、“放弃原重试，开始新操作”，刷新后需重新选择
  原文件才能重试；不支持拖放，没有逐文件进度。
- 页面详情直接展示 SHA-256、以 `B` 为单位的原始字节数和版本游标参数，没有
  区分常规视图与技术详情。
- 非主 Token 模式下，每次标签变更或恢复都要重新输入 Operator Token。这是有意的
  安全设计，但对连续操作非常不便（见总览开放问题 2）。

## 七、内容浏览

- Markdown 正文默认以转义后的 `<pre>` 纯文本显示，安全渲染预览位于另一条路由。
- 普通详情的文件集正文预览只识别 `content.md`，其他名称的 Markdown 即使可以在
  渲染页选择，也可能在普通详情显示“没有可安全预览的正文”。
- 网页上不能编辑正文，修订只能通过整组上传文件完成。
- 历史版本只是 “版本 N” 链接列表，不能比较两个版本之间的差异。

## 八、视觉

- 单份手写样式表，没有设计令牌、图标体系或暗色模式。
- 按钮几乎都是同一种绿色，主要、次要、危险操作区分不足；大量操作是样式化的
  链接（`a.button`），语义与外观不一致。
- 已有 viewport、可换行网格与窄屏样式；窄屏侧栏主要改为横向滚动的全局菜单，
  尚未形成内容目录与编辑预览的完整响应式工作区，不能描述为完全没有适配代码。
