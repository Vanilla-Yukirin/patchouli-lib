# 凭据管理与一次性接入小票

状态：已接受产品方向；本提案和实现一起提交审查，尚非稳定接口承诺。

## 问题与范围

管理页面签发的是供程序使用的凭据，并不创建或启动外部 Agent。界面统一使用
“凭据管理”“创建凭据”“凭据名称”“凭据说明”，保留现有内部 Caller、Agent
类型和路径兼容。一个设备可以保存多份用途不同的凭据；凭据名称是用途标签，
不强制等于物理设备名或人类账号，也不承诺进程间隔离。

既有本机隐藏输入长期 Token 的方式继续保留。新增“接入小票”让用户通过聊天
交给本地 Agent 一个短期、单次的签发能力，长期 Token 由本地脚本直接保存。

## 明确的授权边界

主 Token 登录者在网页生成小票，不预先设置库范围或长期凭据期限。持票者可在
兑换时选择普通凭据的名称、说明、有效期，以及独立的读取与写入范围，包括
全部现有和未来知识库及永不过期。小票不能签发主 Token 或 operator，不能登录
管理后台、改服务器或执行 SQL。生成页面必须清楚说明持票者的签发能力。

用户在凭据管理页点击一次即可生成小票，结果在同页右侧抽屉展示，包含短码、
剩余时间和复制按钮；较长的接入指令默认折叠。无需二级生成页面，不清空正在填写
的凭据表单。失败在抽屉内说明原因，只有会话确实失效才提示重新登录。页面沿用
全站同源来源策略，避免浏览器隐藏来源与提交校验互相冲突。

Agent 在兑换前询问并确认上述信息及本地存储变量名。服务端不能验证 Agent 是否
实际询问过用户；小票本身就是这次签发授权。收到未兑换的小票的人可抢先兑换，
因此不能称它为无敏感性的验证码或保证可公开发布的字符串。

## 票据生命周期与兑换

- 使用密码学安全随机源生成 16 个字符，非容易预测的数字序列；服务器仅存摘要。
- 自生成起 300 秒有效，成功兑换一次后永久失效；不因失败或查询延长有效期。
- 生成要求有效主会话、来源检查及 CSRF；票据绑定签发时的主身份与安全代次，
  主凭据重置使旧票失效。不存在可用主身份时不能兑换。
- 兑换接受严格的名称、说明、寿命和独立库范围参数；沿用现有凭据验证，不隐式
  把写权限扩成读权限，不默认为全部授权。不支持未知库、主身份类型或任意附加字段。
- 对具体库选择提供持有效未消费小票的有限只读发现，只返回选择所需的库标识和
  名称；不返回文件内容、其他凭据或主身份。不允许匿名列库，查询不消费票据。
- 验证、票据消费、身份与凭据创建、策略和审计必须在同一写事务完成。并发兑换
  最多一个成功，事务失败不消费小票，也不留下部分凭据。
- 无库、无效参数等签发失败不消费小票。过期、已用、不存在、主代次失效使用
  统一拒绝，避免暴露不必要状态。尝试受有界限流，明确多进程部署的限制。
- 成功响应仅一次返回长期 Token 并禁止缓存。网络响应丢失时禁止自动重新生成
  小票或新增凭据；用户在管理页面确认已创建结果并再次显示或吊销。
- 票据和 Token 不放 URL，不写入请求日志、错误正文、审计详情或公开接入提示词。
  长期 Token 不进入模型输出；一次性小票可按用户意图进入对话，但仍按短期秘密处理。

## 本机多凭据流程

用户为不同用途创建独立凭据，并自定义环境变量名，例如
`PATCHOULI_TOKEN_EDITOR` 和 `PATCHOULI_TOKEN_READER`。接入流程先选择唯一变量名，
发现已有值时停止并询问，不静默覆盖，也不自动退回其他凭据。

支持 Windows 用户级持久环境变量、Linux/macOS 的用户选择环境文件或 shell 配置。
只有用户明确选择持久保存才写入；给具体 shell 写配置时需说明非交互进程可能不加载
该文件。写入必须保留其他内容和原权限，避免重复定义或 shell 注入，不通过带秘密
字面值的命令行完成。默认不建立新的凭据管理服务或要求专用 CLI。

本地脚本执行兑换、保存、重新读取、whoami 和能力检查。输出只含保存是否成功、
凭据 ID、名称、有效期、实际权限等必要非秘密状态；不输出兑换 HTTP 原始正文，
不把长期 Token 先读到模型再保存。保存失败时保持秘密不回显并让用户通过管理端
恢复，不为了“重试”再次签发。环境变量是便利存储，不是不同 Agent 的安全隔离。

Skill、全局 AGENTS.md 或用户选择的记忆位置只记录服务入口、变量名、用途和使用
规则，不记录凭据值。共享 Skill 不硬编码某个 Agent 的个人变量名，不修改未授权的
其他 Agent 配置。通用接入提示词包括两条路径：本机隐藏输入，或用户提供接入小票。

## 持久化与兼容

新增 SQLite 迁移和票据表，不重写已有内容、凭据或授权。备份精确结构检查覆盖
新表及票据约束，同时继续验证已有历史版本；升级前停写并备份属于独立部署流程。
恢复旧备份会恢复当时的授权状态，包括未过期未消费的小票状态，短期过期检查仍
使用服务器当前时间；本期不引入数据库外的代次文件。首版保留票据审计历史，不提供
删除票据的入口；数据库阻止删除或重写已消费记录，任何票据记录存在时均拒绝降级。
备份验证票据和创建审计一一对应，以及成功消费与凭据签发的一致性。

## HTTP 契约

公开 `/connect` 提供不含秘密的接入引导。主会话在管理页生成小票后，持票者通过
`POST /api/v1/onboarding/libraries` 查询选择范围所需的库 ID 与名称，再通过
`POST /api/v1/onboarding/redeem` 签发普通凭据。两者均使用 JSON 请求体传票据，
不使用 URL 参数；完整字段和本地保存流程见随服务发布的
[接入小票 Skill 参考](../../skills/patchouli-agent/references/onboarding-ticket.md)。

两个端点共享每 worker 每 60 秒 60 次的有界尝试计数，失败尝试同样计数；多 worker
各自计数，不承诺全部署统一限额。请求体最多 128 KiB。无效小票统一 401，参数错误
422，名称冲突 409，限流 429；签发成功 201，并只在此响应返回长期 Token。

## 替代方案

本机隐藏输入长期 Token 无需新增兑换接口，继续支持。网页预先限制小票的库范围
和寿命可缩小泄漏影响，但本期选择生成后由用户与 Agent 商定参数。主 Token 直接
交给 Agent 会扩大管理权限且暴露长期密钥，不作为接入方式。

## 验证清单

- 16 字符生成、摘要存储、严格五分钟边界、一次消费、并发竞争、失效主代次。
- 输入错误、无库、未知库、数据库和审计失败均无部分签发；成功含正确独立范围。
- 限流、请求体大小、验证错误、日志和响应缓存不泄露小票或 Token。
- 主会话、CSRF、来源检查、中英文文案和普通凭据权限不能调用生成入口。
- 迁移往返、历史及新备份校验、降级防丢失；凭据与内容原样保留。
- Skill 场景演练：缺少参数先询问；不回显秘密；自定义变量与冲突处理；兑换响应
  丢失或保存失败停止重复签发；独立读写权限和 whoami 核验。
