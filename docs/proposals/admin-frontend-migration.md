# 管理前端迁移计划

- 状态：提案中（Proposed）
- 范围：管理端 JSON 接口、新前端工程的引入方式、前后端边界、阶段划分、安全要求与
  验证；Agent 公开 API 只做增量扩展

[工作区与库内 Skills 产品需求](library-workspace-and-skills.md)补充了文本编辑、写入
时标题与库内规则包。这些与前端迁移在同一轮开发中交付；下文的阶段只表示依赖顺序，
不是分批发布的节点。每个领域扩展（入口文件与标题、Skills 实体、备份迁移）仍须先
定出契约并通过必要检查，再实现。

## 总体方式

采用新旧并行、逐页替换：

1. 为管理面板新增只接受管理会话的 JSON 接口；
2. 新前端先挂在 `/admin/next`，与现有页面共用登录会话；
3. 按阶段逐步迁移，每阶段达到验收标准后再进入下一阶段；
4. 功能对齐后把 `/admin` 切换到新前端，删除旧页面及其全部服务端渲染代码。

## 前后端边界

- Python 侧最终只保留：领域服务、管理端 JSON 接口、Agent 公开 API 与 MCP、前端构建
  产物的只读静态托管。不含 HTML/CSS/JS 字符串、服务端模板和服务端 Markdown 渲染。
- 前端工程 `web/` 独立构建、独立测试，不 import 任何 Python 代码；两者只通过管理端
  JSON 接口及其生成的 OpenAPI 类型交互。
- 运行时同源：构建产物由本服务（或同源反向代理）提供，管理会话 Cookie 与 Origin
  校验保持不变，不引入 CORS。
- 登录、退出与首次设置也走 JSON：`POST /admin/api/session` 建立与现在语义相同的
  签名 Cookie；`GET /admin/api/session` 返回当前身份模式和 CSRF 值，前端把 CSRF 值
  放入写请求头。语言、主题等非敏感界面偏好保存在浏览器本地，不使用服务端 Cookie。
- 公开的 `/connect` 接入页属于 Agent 公开 API 一侧，本轮保持不变。

## 管理端 JSON 接口

- 路径前缀暂定 `/admin/api/`，与 Agent 公开的 `/api/v1/` 分开；
- 复用现有 `AdminReadModel`、`AdminActionService` 及各领域服务，不复制业务逻辑；
- 只接受管理会话 Cookie，不接受 Bearer 凭据；写请求要求同源 Origin 与
  请求头中的 CSRF 值；
- 并发语义分两类：文本与文件组保存采用“基于最新版本覆盖”，由接口显式表达，被取代
  的版本保留在历史中；移动、移入回收站、标签变更等仍沿用 `expected_updated_at` /
  `expected_etag`，不一致时返回 `409` 和机器可读的错误码；Agent 公开 API 的并发
  契约不变；
- 文档版本的文件清单为每个文件给出名称、大小、摘要、下载地址，以及（仅当服务端允许
  预览时）预览地址；可预览性、图片重新编码等决定仍由服务端作出，前端不自行拼接
  路径或判断；
- 含入口文件与已保存标题的字段随版本返回；
- 错误响应使用统一结构（错误码、可本地化的消息键、字段错误列表），不在响应中
  回显凭据；
- 生成独立的 OpenAPI 文档，供前端生成类型；该文档不并入公开 API 文档；
- 含一次性凭据的响应继续设置 `Cache-Control: no-store`。

## 前端工程

- 位于仓库根目录 `web/`（目录名待确认），独立的 `package.json` 与锁文件；
- 构建产物在镜像构建阶段生成，由本服务以静态文件形式在 `/admin/next`（后期为
  `/admin`）提供；未匹配的前端路由回退到入口 HTML；
- 入口 HTML 与静态资源沿用现有安全响应头；带哈希的静态资源可长期缓存，入口 HTML
  禁止缓存。

## Markdown 渲染与标题契约

渲染在前端完成，阅读与编辑预览共用同一个渲染器。规则从现有服务端渲染器
（`markdown_preview.py`）移植，行为保持一致：

- 使用 CommonMark 兼容解析；不渲染原始 HTML，不自动识别裸链接，不做排版替换；
  启用表格；
- 图片只引用同一版本内的同级文件，且只在文件清单给出预览地址时显示（服务端提供的
  PNG/JPEG 重新编码预览）；SVG、远程图片、`data:` 地址和子目录一律不加载，显示为
  图片的替代文字；
- 链接：指向同一版本内同级文件的链接使用清单中的下载地址；外部链接只允许 `https`
  并带 `rel="noreferrer noopener"`；其他目标降级为纯文本；README 可使用根相对链接
  指向本地 Skills；
- 超过 1 MiB、不是合法 UTF-8 或含 NUL 的内容不渲染，改为显示转义的源码；
- 渲染结果再经 DOMPurify 净化，作为纵深防御。

标题提取在写入时由 Python 完成，取入口文件的第一个一级标题（规则见产品需求）；
前端编辑预览用同样的规则实时显示。两端共用一份测试向量文件，由 `pytest` 与 Vitest
读取同一份数据，任一端规则变化都会使另一端测试失败。

## 安全与 CSP

新前端需要的 CSP 变化应尽量小：

- `script-src 'self'`：全部 `/admin` 页面需要，替代现有的按页开启；
- `connect-src 'self'`：用于调用管理端 JSON 接口；
- `style-src 'self'`：Tailwind 构建期生成静态 CSS，可满足；Radix 通过 DOM API
  设置的行内样式不受该指令限制，实现时需实测确认；
- `img-src 'self'`：用于同源图片预览；
- CodeMirror 等需要插入样式元素的库，使用由服务端为每次响应生成的 nonce，
  不使用 `'unsafe-inline'`；实现前需验证；
- 前端渲染 Markdown 不使用 `eval`，也不放宽上述指令。

是否以 ADR 形式记录上述变化，见[总览开放问题 1](admin-frontend-rebuild.md#开放问题)。

## 阶段

阶段按依赖顺序排列，同属本轮交付。

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| 0 | 本提案审查；[小修清单](admin-frontend-quick-fixes.md)并行推进 | 提案合并；开放问题有明确负责人 |
| 1 | 搭建 `web/` 工程、构建与镜像打包、同源静态托管；会话 JSON 接口；`/admin/next` 外壳、登录、语言与主题切换 | 镜像构建通过；CSP 无违规；未登录跳转登录页 |
| 2 | 入口文件与写入时标题的存储与迁移；前端 Markdown 渲染器与共享标题测试向量；只读浏览：顶部导航、知识库概览、分区阅读目录、版本历史、文件下载、当前库/全局搜索 | 旧内容可读，无入口文件时按规则显示；历史标题不变；键盘与窄屏均可浏览 |
| 3 | 内容写操作：文本源码与预览、明确保存并保留附件、新建文档、上传、移动、回收站与恢复、版本恢复、标签、README 与描述编辑、发生时间 | 既有历史不变；保存冲突覆盖后旧版本可在历史找回；幂等与重试边界通过必要检查 |
| 4 | 附件改名与引用调整 | 改名与所选引用同一版本提交；编辑后旧建议失效；不修改历史 |
| 5 | 库内 Skills：实体、路径、版本与备份迁移的契约 → 网页查看与编辑 → Agent 下载与清单 → 本机安装与版本同步 | Agent 可下载并核对摘要；备份往返不丢失；服务器不执行包内脚本 |
| 6 | 管理与凭据：凭据创建／轮换／吊销／再次显示、范围授权、API 请求日志、初始化与首次设置 | 一次性凭据不进入缓存或存储；审计记录与旧页面一致 |
| 7 | 切换 `/admin` 到新前端，删除旧页面及服务端渲染代码 | 功能对齐；旧页面及其测试已删除 |

阶段 2 起即可邀请使用者试用 `/admin/next` 并收集反馈。仅做界面原型时，不把虚拟数据
当作已经持久化或能够供 Agent 下载。

## 测试

维护者在桌面、平板和手机宽度下对视觉与交互做目视验收，自动化测试保持精简：

- 管理端 JSON 接口：在 `tests/admin/` 中新增接口测试，覆盖鉴权、CSRF、同源、
  覆盖保存与 `409` 路径、字段校验与错误结构；
- Markdown 渲染器与标题提取：共享测试向量（含代码块、front matter、Setext 标题、
  非 Markdown 入口文件、无入口文件）；
- 前端组件：Vitest + Testing Library，仅覆盖复杂交互（编辑器、引用调整窗口、上传
  队列）；
- 端到端：Playwright 只覆盖核心旅程（登录、阅读、编辑保存、新建、移动、回收与恢复），
  使用合成凭据与按任务隔离的临时数据库，测试后清理临时数据；
- 复用现有浏览器冒烟与接口检查，不为相同业务在多个层次新增重复旅程或矩阵；
  文案和展示细节优先轻量检查；
- 现有 `tests/admin/test_*_browser.py` 在对应旧页面删除时一并移除，其中的业务
  断言迁移到接口测试。

## 协作与文件归属

依照 [Agent 贡献工作流](../agent-contribution-workflow.md)：

| 工作 | 写入范围 |
| --- | --- |
| 小修 | 现有 `src/patchouli_lib/admin/` 页面、路由与对应测试 |
| 管理端 JSON 接口 | 新增的管理端接口模块及其测试 |
| 新前端 | `web/` |
| 内容模型扩展（入口文件、标题、Skills） | 内容与迁移相关模块，由集成者串行审查迁移 |
| 构建与镜像 | `Dockerfile`、`compose.yaml`、验证脚本，由集成者串行修改 |

同一路径在同一时间只由一名写入者负责；涉及安全响应头与 CSP、数据库迁移的修改由
集成者统一审查。

## 风险

- **新旧两套界面并存期的维护成本**：通过限制小修范围、尽快完成阶段 2 控制；
- **CSP 兼容性**：组件库或编辑器若需要内联样式，可能迫使放宽策略；须在阶段 1
  用实际依赖验证，不满足时替换依赖而不是放宽 CSP；
- **渲染与标题规则分叉**：前端渲染器与 Python 写入端是两套实现，靠共享测试向量
  约束；解析库选用同一规范族（前端 `markdown-it`，后端已有 `markdown-it-py`）；
- **一轮交付范围大**：各阶段保留可回退到上一阶段的检查点；领域扩展先定契约；
- **镜像体积与构建时间增加**：前端构建在独立构建阶段完成，最终镜像只包含静态
  产物；
- **测试改写工作量**：现有 HTML 断言测试需要随迁移逐步替换。
