# 主会话网页文件集写入与重试记录

状态：提案中（Proposed）。本文件细化已确认的网页上传目标。开发分支已加入
主会话写入服务与持久成功记录的实验实现；网页入口尚未接通，尚未合并或部署，
也不改变其他提案的状态。

## 1. 范围与现有底座

目标是在管理网页中，用已登录的单人主身份创建 Page 或更新现有 Page 的整组文件。
不需要另外填写 operator 或 Agent Token。单份 Markdown、多文件和纯二进制内容
走同一流程，仍不接受 Page 内嵌套目录。

开发分支已有角色无关的首版创建核心和整组修订核心，以及 Agent 的文件集 HTTP
编排。核心在调用方授权后的真实 SQLite 外层事务中写内容，不能单独当作已完成
的管理操作：主会话鉴权、内容审计、成功重试记录和事务提交仍需外层负责。
网页下载已有精确版本和完整文件组校验，可作为上传后核验的读取底座。

本切片不增加远程免鉴权注册、不执行上传的脚本、不在浏览器内联执行原始文件，
不扩展 Agent 的公开 HTTP 契约。Page 移动、指定版本回滚和声明时间校正是另行
接入的管理操作，不因上传页面出现而自动完成。

## 2. 网页操作

Book 详情提供“新建文档”，现有 Page 详情提供“更新文件”。优先使用已有的
本地样式、标准文件选择框、输入框、按钮和状态提示，不引入新的前端框架或外部 CDN。
创建填写标题、可选声明时间并选择文件；修订明确展示当前版本和完整文件清单，
说明提交的是整组替换，未选入的新快照文件不会保留在新版本中，但旧版本仍保留。

浏览器使用少量同源外部脚本组织上传：首个 multipart 部分为 `metadata` JSON，
随后是多个 `file`。传输继续使用现有有界解析器和文件名、数量、单文件与整组大小
规则；不按文件数区分单 Markdown 和多文件接口。文件选择和预览不能读取服务器
磁盘，也不能把用户选中的文件送给第三方。

现有 Agent 解析器要求无文件名、`application/json` 的 metadata 部分，而浏览器
`FormData` 的字符串部分通常没有该类型，使用 Blob 又会附带文件名。因此网页
入口需显式允许首个无文件名的 JSON 字符串 metadata 变体，保留相同的 metadata
字节预算、结构验证与文件限制；该选项默认关闭，不能改变现有 Agent API 的严格
输入规则。必须用实际浏览器构造请求验证，不能只凭手写 multipart 测试声称兼容。

开发分支已加入默认关闭的 `allow_browser_metadata` 解析选项及定向测试；显式启用
时接受无文件名的 JSON 字符串部分，大小、顺序和文件限制不变。现有 Agent 路由
不启用该选项。测试使用真实 Node.js `FormData` 序列化验证传输差异，尚不是网页
表单、主会话写入入口或实际浏览器端到端验收；这些接入仍待完成。

上传前先核对同源、签名会话及 CSRF 请求头，再读取有界请求体。CSRF、Cookie、
原始重试键和文件正文不得进入日志或内容活动。拒绝响应不能回显这些材料。
脚本只允许同源资源与请求，不能为上传扩大为任意脚本源或 `unsafe-inline`。
没有脚本时给出明确说明，不能静默提交不完整的文件集。

创建和修订使用各自的随机操作键；同一次重试保留原键、原目标、原元数据和原文件。
仅禁用按钮不足以防重：断网、刷新或响应丢失后，仍需服务端持久成功记录。
用户改选文件或改变元数据时应开始新操作，不能复用旧键。修订还携带打开表单时
的强 Page ETag；发生并发变化时保留用户本地文件并提示重新读取，不自动覆盖。

成功结果给出本次 Page、准确 Revision、文件清单摘要及当前操作是否改变内容，
并链接精确版本预览。历史成功重试可能指向较早 Revision，不能误标为当前内容。
后续 Page 更名、删除或移动时，旧成功记录不负责复原其当前路径或重新创建 Page。

## 3. 主身份成功记录

候选表为 `admin_master_file_set_receipts`，与绑定 Caller 的 Agent 幂等表分开。
操作命名空间使用稳定主身份 ID、操作种类和原始操作键的摘要，不包含会话代次。
主 Token 轮换后旧 Cookie 必须拒绝；同一主身份的新有效会话可以重放其历史成功。
不能把“找到回执”当成允许旧会话继续访问的理由。

记录最少包含：

- `identity_id`、`operation`、`key_digest`，共同构成主键。
- `request_fingerprint`，证明本次语义请求与原成功操作一致。
- 原成功目标的 Library、Section、Book、Page ID 及稳定 Page UID。
- 准确 Revision ID／编号、完整文件组摘要和 `changed` 标记。
- `original_occurred_at`、`original_page_updated_at`、`response_etag` 及服务器操作时间。
- 有变化时的准确 Source ID 和主审计事件 ID；无变化时这两项为空。

键摘要、请求指纹及快照摘要为 32 字节。文件字节仍只存 Revision，不复制进回执；
原始 Token、Cookie、CSRF、操作键、HTML 和任意跳转 URL 不存进回执。
响应链接根据已验证的实体标识构造。回执只插入、不更新或删除；Page、准确 Revision、
Source 与主审计关联使用限制删除的外键，不能物理删除对应历史后还保留成功证明。
Source 和主审计链接各自唯一，防止多条回执冒领同一变更事件。
原成功的 Section／Book 是历史目标。当前尚未实现 Page 移动，因此验证要求它们与
Page 当前归属一致；未来接通移动时须先保留并核验历史归属，再替换这项当前路径
检查。不能跳过归属验证，也不能用移动后的路径覆盖原成功记录。

主身份 ID 按历史身份保存，不给回执设置指向当前单例身份行的级联关系。
创建必为有变化的版本 1；无变化只适用于修订，不新增 Revision、Source 或内容活动。
旧单 Markdown Page 的相同文件组修订可以是无变化；若实际变更则追加完整文件组
Revision，不改写旧 Markdown 历史。

请求指纹使用有版本和操作域的长度分帧摘要，包含目标路径、标题、显式声明时间
（未填与填写的区别）、Source 语义、修订 ETag，以及规范排序的每个文件名和完整
字节。规范化后的文件顺序不影响身份，multipart boundary、Cookie、CSRF 和当前
会话代次不影响身份。不能只用某个 Markdown 哈希或文件总大小代替完整请求证明。

## 4. 单事务编排

有界解析和输入验证后开启一个短 `BEGIN IMMEDIATE` 事务：

1. 在该事务内重新核对当前主身份与会话代次，拒绝在等待锁期间已失效的会话。
2. 按稳定身份、操作及键摘要查成功记录。指纹不同则冲突，不允许改写回执。
3. 命中同一请求时，核验已存准确 Revision、整组文件和回执链接，再返回原成功结果。
4. 没有回执才检查新写入目标、未删除状态及修订的当前 ETag，然后调用内容核心。
5. 有变化时读取并关联内容核心已经生成的唯一精确 Source，再增加脱敏主审计；
   不重复插入 Source。无变化时不新增 Source 或内容审计。
6. 写成功回执并核验内容、审计及回执后一起提交。任一步失败均整体回滚。

重放在新请求的当前 ETag 检查之前，避免已经成功的修订被自己的新版本挡住；
但鉴权必须始终在重放之前。其他新修订、标题或声明时间变化后，旧回执仍描述
原成功状态，不要求其 ETag 等于当前 Page ETag。回执的两个原时间字段不可省略：
当前 ETag 同时包含声明时间和 Page 更新时钟，仅存 Revision 指针无法重放旧结果。

索引由同事务内容写入维护。重放和无变化不生成重复内容活动；API 请求记录仍按
现有脱敏范围单独采集，不把每次请求变成一次文档变更。

## 5. 候选迁移与备份

开发分支的实验迁移 `0026` 新增表和不可变触发器，不重写既有 Page、Revision 或凭据。
已有历史不自动生成网页成功回执。产生任一回执或对应主文件集审计后，降级不得
丢失这些记录；空表和无相关主审计时才允许撤回这次迁移。

备份默认版本随迁移推进，但必须保留 `0025` 的结构哈希、主删除历史和旧备份
验证分支。不能把此前仅适用于“当前版本”的判断直接替换成 `0026`，导致合法
`0025` 备份不可验证。恢复仍按备份准确版本落到新目标，不自动升级或重签凭据。

除结构、外键和文件封印外，验证必须核对回执目标、准确 Revision 与整组摘要，
重算原成功 ETag，并证明其时间组合属于该 Revision 的有效历史状态。
有变化的记录必须对应唯一 Source 和正确主审计动作、身份、目标及操作时间；
对应主文件集审计反向也必须有回执。无变化不能带 Source 或主内容审计链接。

恢复较早的完整数据库也恢复当时的回执集合，备份之后的成功记录不再存在。
因此不承诺跨数据库回滚的全历史幂等性；重试前应核对恢复后的 Page／Revision。
备份的含明文 Agent Token 机密属性和旧凭据状态回滚语义保持原决定。

## 6. 验收清单

- 同键同请求只创建一次，同键异请求明确冲突；结果丢失后可重放。
- 文件选择顺序变化不重复创建，字节或目标变化不能冒充重试。
- 单 Markdown、混合文件、纯二进制和旧 Markdown 转文件组均准确回读。
- 相同内容修订无新版本、无重复 Source／内容活动，但成功记录可重放。
- 旧 ETag 新请求拒绝；已成功的同键请求在后续修订、更名、时间校正或回收站
  操作后仍描述原成功，不把 Page 重新创建或恢复。
- 主 Token 轮换前的 Cookie 拒绝，轮换后有效新会话可重放；旧密码／operator
  会话不能调用新主身份写入入口。
- 同源、CSRF、multipart 边界、大小／数量／文件名限制及安全 CSP 有真实应用测试。
- 内容、Source、主审计或回执写入故障时全部回滚，不留下成功提示或部分文件。
- 新旧迁移、降级守卫、旧 `0025` 验证、含回执备份恢复和篡改拒绝有合成测试。
- 管理近况只显示实际创建／修订，不显示无变化或重放为新活动；精确版本链接可用。

所有测试使用合成数据。真实资料导入、备份恢复和服务更新仍按独立的运维授权执行。
