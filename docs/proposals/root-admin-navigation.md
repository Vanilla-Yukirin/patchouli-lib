# 启用管理面板时的根地址导航

- 状态：提案中（Proposed）；实现随本提案提供，长期兼容性仍由公开 API 策略确定
- 范围：`GET /` 的导航行为；不修改数据库、登录、授权或部署入口

## 问题与方案

管理面板启用后，用户打开服务根地址仍会看到工程骨架的 JSON 信息，需要手动补上
管理页面路径。将 `GET /` 调整为返回 `307 Temporary Redirect`，目标固定为同源
相对地址 `/admin`，并设置 `Cache-Control: no-store, max-age=0`。

`/admin` 继续使用既有会话检查：未登录的请求进入登录流程，已登录的请求显示面板。
根路由不读取或复制凭据，不使用请求参数、Host 或转发头生成外部跳转地址，也不要求
Cookie 扩大路径范围。不同域名和非默认端口均由浏览器按当前入口解析。

管理面板关闭时，根地址继续返回原有服务信息 JSON，避免跳转到未注册的页面。
`/health/live` 和 `/health/ready` 保持原有 JSON 健康检查契约。

## 兼容性与取舍

启用面板的安装中，读取根地址 JSON 的调用方会收到重定向；健康监测应使用专门的
健康检查接口。OpenAPI 同时记录原有 JSON 与条件重定向响应。
该行为暂不作为稳定兼容承诺，也不会自动更新任何运行实例。

相比按浏览器 User-Agent 或 Accept 猜测调用方用途，按明确配置判断入口行为更一致。
使用临时重定向和禁止缓存，避免客户端永久记住取决于当前面板配置的跳转。

## 验证

覆盖面板关闭时的 JSON、面板开启后的匿名与已登录导航、不同域名和非默认端口，
以及既有健康检查。测试只使用合成凭据和临时数据库。
