# Agent 同库 Page 移动

- 状态：提案中（Proposed）。记录已接受的 Agent 可自主普通移动目标的候选后端契约，
  不改变其他提案状态，不表示已发布、部署或真实资料验收。
- 范围：只有显式逐 Library 授权的 Agent，持目标 Library 的 `write`，才能移动该库
  未删除 Page；可跨 Section，不跨 Library，不删除或重组层级。
- `write` 不隐含 `read`。有效的旧 Section 和 operator 凭据调用此入口返回 403，
  不把新能力自动授给旧凭据。主 Token 不作为该 Bearer 接口的凭据，传入时返回 401；
  主会话继续使用既有管理入口。

## 请求与原成功重试

`POST /api/v1/libraries/{library_id}/pages/{page_id}/move` 不重定向。
JSON 正文只有 `source_section_id`、`source_book_id`、`target_section_id`、
`target_book_id` 四项；它们必须是完整、准确的同库归属，禁止多余或重复字段。
必填单一 `Idempotency-Key` 和当前强 `If-Match`，沿用文件集写入的键和 ETag 校验。
正文上限 1,024 字节；不读取文件、不上传字节或制造新 Revision。

身份与目标库写授权在收正文前检查，在真实 `BEGIN IMMEDIATE` 内再次核对。
库、Page ID、原源／目标归属和原 ETag 共同绑定语义指纹；重试必须完全重复原请求。
成功命名空间包含目标 Library、操作者 home Library、Caller、POST、新路由与键摘要。
利用领域隔离的 home-bound 键摘要显式绑定身份归属，不改变旧路由的键规则；当前
Caller ID 本身也全局唯一。凭据轮换不改变稳定 Caller 命名空间，仍须新凭据当前获权。

当前授权先于重放及指纹冲突；失权不能读出旧成功，也不能探测旧键是否属于另一请求。
有权的旧成功即使其 Page 后来修订、移动或删除，仍仅返回原成功，不再次移动、不复活。
新键必须匹配当前归属、未删除状态与当前 ETag。同目标返回 `changed=false`，持久保存
成功但不新增移动事件或内容活动；后来同键不能变成真正移动。

响应 200 只含源／目标身份、Library／Page ID、未变的 Revision ID／序号、声明时间、
原／结果更新时间、原请求 ETag 与 `changed`。响应 `ETag` 为原成功结果 ETag，
重放加 `Idempotency-Replayed: true`，正文和 ETag 不改写。它描述当时成功位置，
不是 Page 现在的位置，不含标题、正文或文件清单。实时位置另用既有稳定发现接口，
需要独立 `read` 权限。旧深层 URL、历史响应与 `revision_url` 不被改写。

错误沿用受保护 API：失效凭据 401；无逐库写权限或旧模式 403；不可用源／目标 404；
同键不同请求 409；旧 ETag 412；正文超限 413；不支持媒体类型 415；无效请求 422；
缺 `If-Match` 428。错误不回显 Token、键、正文或私有数据库异常。

## 持久化、审计与备份

0029 延续同一 `page_move_events` 连续不可变链和准确消费的 guard，增加互斥的
Caller 审计关联；一个事件只属于真实主审计或真实 Caller 审计之一。Caller 审计
记录准确凭据、操作者 home Library、Caller、目标 Library、Page、请求 ID 与逻辑
变更时间，不伪造主身份。主会话的旧成功表和旧事件值原样保留。

角色中立核心只在调用者真实写事务中检查源／目标／ETag，并应用 guard 与归属更新。
鉴权、审计、持久成功及索引仍由外层同事务完成，任何失败回滚；Page ID、内部 UID、
标题、Tag、声明时间、内容历史及 Source 均不改变，逻辑更新时间严格递增。
Caller 成功沿用通用幂等表并验证准确历史状态、原／结果 ETag、请求指纹与真实审计。
事件、审计、改变成功须双向唯一对应；无变化成功须证明同一准确历史状态。

保留 0028 及更早修订号的精确结构哈希和原格式恢复，不将默认 head 当特性号。
0029 使用独立结构哈希；混合主／Caller 历史继续供旧回执和当前活动链接验证。
存在 Caller 移动、无变化成功、遗留 guard 或孤立移动审计时拒绝有损降级。
普通 SQLite 触发器仍不能在 COMMIT 自动查出孤立审计或缺成功记录的完整事件；
正常服务负责原子齐备，备份负责完整双向验证，不宣称任意手写 SQL 都安全。
