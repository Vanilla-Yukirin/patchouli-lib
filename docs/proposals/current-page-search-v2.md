鉴权范围核对、索引就绪门槛、有界摘录和不透明续页游标；旧单 Section 搜索路由

本文把[下一阶段产品目标](next-phase-product-and-api.md#8-当前-revision-的真实搜索)
细化为可审查的搜索设计。它不改变[历史 FTS5 Alpha 提案](fts5-current-revision-retrieval-alpha.md)

仍须经公开审查、迁移与测试才可成为兼容性承诺。

## 已接受的可观察查询语义

- `keywords` 是字面字符串数组；任一项在同一字段内连续命中即可召回，更多不同
  项命中可提高排名。不做模糊纠错，也不把 Tag 显示名当关键词。
- `tags_any` 按任一指定 Tag 命中；Page 声明发生时间按可单独省略端点的 UTC
  半开区间硬筛选。两种筛选不以权重代替。
- 省略 Library 选择时，搜索凭据**实际可读**的全部 Library；旧 Section grant
  仍受其原有范围限制，不因跨库搜索而扩权。
- 只有 Tag 或时间条件时也能查询；完全空条件不执行搜索，网页引导使用浏览页，
  API 明确提示使用浏览接口。
- 首版采用确定性的固定字段权重，具体数值须经独立相关性语料评估；搜索结果以
  Page 为单位，仍须通过迁移、重建、备份和容量／性能验收。

新搜索采用跨 Library 的 POST 契约。开发分支已移除旧单 Section 搜索路由，
新路径不沿用旧路径的含义；客户端／CLI／MCP 对应旧入口也在本分支退役，
并在变更日志标明不兼容变更。

## 目标与范围

- 返回**未删除 Page 的当前 Revision**，一项结果对应一个 Page；旧 Revision
  只由明确的历史读取接口访问。结果附稳定 Page ID 和准确 Revision ID。
- 同一请求可在调用方有读权限的多个 Library 内搜索；普通调用方不能因搜索获得
  额外 Library、Section 或 Page 权限。旧 Token 的既有授权不能被迁移隐式扩大。
- 支持中文连续单字、双字、三字及中英混合字面查询；不依赖向量、远程模型、外部
  分词词典或高级 FTS 查询语法。词项用于召回，排序须另行证明相关性。
- 支持关键词、`tags_any`、声明发生时间的组合；允许只有 Tag 或时间筛选而没有
  关键词。对普通宽泛词不截断候选，也不因某个 Section 内容多而拒绝正常请求。
- 正常查询约一秒是评估目标，**不是**允许牺牲完整结果的硬超时承诺。异常输入、
  输出和资源使用仍须有可审查的保护；超限或内部超时必须明确失败，不返回伪装成
  完整 Top K 的部分结果。

文件名、Page 标题和 Page 文件中可安全提取的文本是首版候选关键词索引字段。
现有 Page 没有「说明」字段；Book 摘要与 Section 说明属于上层对象，首版不混入
Page 关键词索引。Tag 的复合身份仅用于 `tags_any` 硬筛选；Tag 显示名不参与关键词
召回。二进制文件的原始字节不会仅因其存入 Page 就自动可搜索；
OCR、转录、PPTX 等解析属于
另行审查的能力。多文件 Page 的索引单位仍是 Page；命中解释应指出具体字段和文件，
不得把文件当成独立 Page 或把文件名冒充全文。正文提取版本也属于索引版本。

生产候选的权威输入来自现有 `pages`、其准确当前 `revisions`、
`revision_file_sets`／`revision_files`、`page_tags` 和声明时间。已有
`search/ngram.py` 只是纯词元提取器，开发分支的新搜索路由使用跨 Library 的
`keywords` 接口。离线评估器使用另造的临时表和额外短词逻辑；
它既未覆盖全部真实写路径，也未定义生产迁移。接入正式应用前，应以同一版本的
提取／查询规则重新验证它们，不能把离线结果直接当作生产验收证据。

## 建议的结构化接口

建议以受 Bearer 保护的 POST 请求承载查询，不把搜索词放入 URL、普通访问日志或
监控标签。开发分支当前请求字段如下；续页游标也位于 POST JSON 正文：
能力响应中的 `limits.max_query_bytes` 是旧接口遗留字段，不限制新请求；新搜索的
限额在索引就绪后由 `limits.search` 公布。

| 字段 | 当前语义与待完成事项 |
| --- | --- |
| `keywords` | 零到多项 UTF-8 字面字符串；非空时至少命中一项，命中更多项可提高相关性。重复项规范化后去重，不被当作 FTS／SQL 语法。 |
| `tags_any` | 零到多项 `(library_id, tag_id)` 复合身份；非空时至少命中其中一项，且只匹配同一 Library 内的 Page。重复项去重；身份所属 Library 不在所选可读范围内、Tag 未知或不可见时整次请求统一安全失败，不静默忽略，也不泄漏对象是否存在。不同 Library 合法地拥有同一个 `tag_id`，不能按裸 ID 匹配。 |
| `occurred_from_us` / `occurred_before_us` | 可独立省略的 UTC Unix 微秒半开区间 `[from, before)`；依据 Page 当前声明发生时间，不依据上传、服务器创建或 Revision 更新时间，也不从 Page ID 的历史时间片段推断。 |
| `libraries` | 可选的 Library ID 列表；结果只来自请求者实际可读范围。显式指定无权访问的 Library 时应使整次请求失败，不返回部分授权结果。省略时搜索全部实际可读 Library；旧 Section 授权不因此扩权。 |
| `limit` | 每页最多返回的 Page 数；当前默认 20 项、最多 100 项，不把响应上限误作内部候选上限。 |
| `cursor` | 可选的不透明续页值；首请求省略或传 `null`，后续请求沿用同一筛选条件、凭据和 `limit`，只将服务返回的 `next_cursor` 放进 JSON 正文。失效或篡改返回 `400 invalid_cursor`，应不带游标重启搜索。 |

开发分支已通过新的 POST 契约实现跨 Library 搜索并退役旧
`/sections/{section_id}/search` 路由及客户端／CLI／MCP 对应入口。查询体应做整体字节、数组
项数和单项长度保护，但正常规模的常见词、宽泛 OR、Tag／时间筛选不因候选过多而
被截断或悄然降级。非法时间区间、重复 JSON 键和不可表示的 Unicode 应明确失败；
任何响应及常规日志都不回显敏感查询正文。

网页可提示用户以空格区分明确的多个关键词；不含空格的中文输入仍应作为一项字面
输入交给搜索器，不能要求用户自己切词。Agent 可直接提交关键词数组，不能拼接
`MATCH`、正则、布尔运算符或 SQL。完全空条件交给独立浏览列表接口，不由搜索
返回默认全库序列。Unicode 归一化、标点、大小写及过短英文词的精确语义仍须在
接口定稿前固定；
每项关键词不得跨字段拼接成一次连续命中。

每项响应包含 Library／Section／Book／Page 身份、当前 Revision ID、标题、
声明发生时间、命中字段／文件说明及至多 240 个 Unicode 字符的纯文本 `snippet`
（有可安全提取的文本时）；页级响应另含 `next_cursor`，启用续页时末页为 `null`。
未配置游标签名密钥的开发环境只返回首批，此时 `null` 不证明结果已穷尽。当前实现未
在每项结果中返回可见 Tag 名称。下载完整内容须再次调用受保护的准确 Revision
接口。摘录从本次已授权当前 Revision 的规范化索引文本提取，不是原文件字节；
浏览器必须将它当文本安全转义，不渲染不可信 Markdown／HTML，也不得泄漏内部索引
词元。公开数值分数、总命中数和高亮偏移仍未定义，不应自行推断。

当前开发分支的响应已返回当前 Revision 的身份和 `revision_files_href`：它是指向
受保护、精确版本文件清单的相对 API 路径，不指向会随更新变化的当前 Page。
目标接口会重新检查读取权限；Page 后续移动、删除或授权变化可能使旧链接失效，
这里不承诺跨这些变化的永久可达性。响应链接、摘录和游标的存在不表示相应提案、
索引迁移或生产部署已获验收。

二进制独占的 Page 仍能凭标题或文件名命中，也能通过 Tag／时间筛选返回；Tag
名称不作为关键词命中字段。若没有可安全提取的正文，不得生成仿佛解析过
二进制内容的摘要。推荐首版只提取明确允许的 UTF-8 文本类型；
不在允许文本类型内的文件只索引文件名。被声明为可索引文本的文件若解码或资源
预算校验失败，应在写入前明确拒绝，或使搜索保持不可用，不能悄然只索引前若干
字节而声称全文已覆盖。可索引字段和文件级命中来源须写入投影版本，使完整重建
可复现。

## 授权、过滤与排序

无论数据库实际先使用倒排、Tag 还是时间索引，**可观察语义**都是：先确定调用者
可读的 Library 和 Page，排除已删除 Page、非当前 Revision，再施加 Tag OR 与时间
区间，最后在该集合内计算关键词相关性、确定全序并取 Top K。SQL 的物理执行顺序
可以不同，但授权过滤不得在全局 Top K、总数、词频统计、游标或摘录之后才进行。

在未授权 Library 加入大量高相关 Page，不应改变已授权范围的候选数量、分数、
顺序、游标或摘录。若使用 IDF／BM25 等语料统计，统计必须只取本次已授权且已选择
的范围；全库 FTS5 `bm25` 不能未经证明就作为返回排序依据。Tag 是跨层级的投影，
不是授权边界；Tag 名称或计数也不能作为无权 Page 的旁路信息。软删除 Page、无权
Page 和旧 Revision 不参与命中、计数或排序。

推荐的权限入口是先把一个凭据在本次请求中实际可读的 Library 集合解析为不可扩权
的范围，再与明确请求的 `libraries` 核对；仅有旧 Section grant 的凭据仍按其原有
Section 边界过滤，不因 0014 授权表存在就自动拥有整个 Library。`write` 是否包含
`read` 也不能由搜索器自行假设。权限、删除状态、当前指针及 Tag 可见性应在同一
一致读视图内判定；先对全库排序／分页再隐藏越权项，会在结果数量和顺序上泄漏
不可见内容。开发分支已接入跨库搜索及逐 Library 授权；该实现尚待整体审查和
生产验收，不能由此推断本段所有候选保证均已得到证明。

首版排序使用确定性的固定字段权重，结合命中的不同关键词数、字段质量及命中的
不同 Tag 数构成可解释得分，
再用稳定 Page ID 决胜；相同 Page 只返回一次。标题、文件名、正文的具体权重，
以及词频、文件长度、时间新旧是否影响分数，**尚未定稿**；Tag 匹配加权只表示硬筛选
命中数，不暗含 Tag 显示名参与关键词召回。Tag 命中数的加权不得把未命中的关键词
或不符合硬筛选的 Page 召回。应先建立独立的相关性判断
集，再比较固定字段权重、仅获授权范围的 IDF 和其他候选；不能让被测排序器同时
生成自己的「正确答案」。任何排序变更须版本化并使旧游标失效。

首个生产候选使用不依赖全库统计的确定性字段权重，以降低越权语料影响和
索引更新成本；对已满足硬筛选的 Page，再比较命中的不同关键词数、命中字段质量、
命中的不同 Tag 数，并以稳定的 `(Library ID, Page ID)` 作最终同分键。具体权重
必须经独立标注语料评估后定稿。若固定权重相关性不足，再比较只在本次获授权范围
计算的局部 IDF／BM25；代价是范围统计、分页一致性与宽泛查询复杂度明显上升。
标题、文件名或正文只要在同一字段连续命中一个关键词便可召回，关键词数组按 OR 取并集，匹配
更多不同关键词才提高排名；Tag OR 与时间是硬筛选，不可拿加权代替。只有筛选
条件时仍须给出可重现的全序，建议先按声明时间降序再用稳定 ID 决胜，排序细节
仍待定稿；完全空条件交给专门的浏览接口处理，避免搜索返回无边界的全库列表。
Tag 显示名不作为 `keywords` 的字面命中字段；`tags_any` 仍按稳定
Tag 身份执行硬筛选。

游标应绑定规范化后的整个请求、所选且实际获授权的 Library 集合、授权版本、
排序／词元版本、派生索引世代及最后一项的完整排序键，并做完整性保护。若权限、
相关内容或索引世代变化，服务应拒绝旧游标并要求从第一页重试，而不是跨两次快照
拼接、漏项或重复。可采用范围版本／快照标识，不应要求长时间持有 SQLite 读事务；
开发分支已用 `400 invalid_cursor` 拒绝失效或篡改的游标；长期游标有效期及
生产验收仍待确定。游标不得包含明文 Token、正文或
未授权对象 ID，也不能由客户端修改排序键。
普通写入不应仅因全局数据库计数变化就令无关 Library 的游标失效，否则无权数据
的活动仍可能形成可观测旁路；推荐采用与已授权范围相关的内容／权限版本。完整
索引重建的原子世代切换可以使旧游标失效，但不能把每次权威写入都伪装为重建。

## 倒排表示的备选与取舍

词元提取、字段投影和查询编译需要同一版本的 Unicode／规范化规则。至少比较：

1. **SQLite FTS5 内置 trigram**：构建简单，但单独使用不能召回一至两个汉字；
   若补短词索引，须证明两个路径合并时不会漏检、重复或改变授权范围。
2. **应用生成 NFC→casefold→NFC 字符词元，写入 FTS5**：一元、二元、三元汉字
   词组与英文数字词元可作为候选。必须把调用方文字编码为数据，不允许成为 FTS
   语法；检查词元爆炸、写放大、索引大小及全局语料统计带来的排序风险。
3. **显式倒排表**：例如版本化的 `(作用域、字段、词元、Page、当前 Revision)`
   行，可直接控制授权谓词、词频和排序统计，但行数、常见词扫描及迁移成本可能更高。

旧 Alpha 的 NFKC＋标点词元不等于本提案的 NFC 字符词元，二者不可混建混查。
规范化形式、Unicode 数据版本、Han 范围、非汉字连续字符、标点边界、文件文本
提取器，以及同一关键词内多个 n-gram 的召回语义，都须组成显式索引版本。Section
可以用于缩小范围，但不能继续作为唯一搜索单位。不得照搬旧 Alpha 的每 Section
1,024 Page、最多 256 候选和全词元 AND 护栏。

推荐先验证「应用产生并十六进制编码字面词元＋SQLite FTS5 召回＋授权范围内的
准确字面复核／排序」；开发分支对**单项且规范化后恰为 1～3 个 Unicode 字符**的
关键词使用字段级完整 gram 的 FTS 行作为准确判定：在当前版本正确生成的索引中，
该 gram 存在与该字段包含这段连续字面文字等价。其他查询继续逐字段做原文字面
复核。此快路径必须保留 FTS 行所对应的确切文件／字段和当前 Revision 约束，不能
只靠 Page 级候选并集推断命中字段；现有就绪检查尚不能验证遭到外部篡改的 gram
内容，因此不把结构就绪说成对任意损坏索引的完整内容校验。

内部 FTS 查询只接收服务生成的安全词元和绑定参数，不把
用户原文解释成 `MATCH` 语法。汉字 1／2／3-gram 可覆盖短中文，但现有纯提取器
对非汉字只保留整词，而离线评估器另加短非汉字词元以覆盖英文子串、符号等测试。
这两套规则不能直接混用。必须先决定英文部分词与标点／表情是否承诺字面子串
匹配，并验证任何索引召回都不会漏掉最终复核认为命中的 Page；若选择只匹配完整
英文词，应明示其与字符子串方案的取舍。对多个词元的一个关键词，可选精确短语
候选或低成本超集召回后逐字段复核；不能只凭某一个 n-gram 命中就把整词判为命中，
也不能因词项跨多个字段而意外认作某一字段的连续命中。

对于常见词或仅筛选条件的查询，执行器必须能在完整合格集合上得出准确 Top K。
数据库可以利用索引顺序、界限证明或早停算法，但需证明早停不会遗漏更高分 Page；
不能先取任意前 N 个候选再排序。保护应针对恶意超长请求、派生词元爆炸、过大输出
及明确的总工作量，而不是把正常宽泛查询当作无效查询。耗时超出目标应作为优化
证据；若资源确实无法完成，请明确错误而不是返回部分结果。

## 写入事务、重建、备份与失败关闭

权威数据是 Page、Revision、当前指针、文件字节、Tag 关联、声明时间、删除状态、
授权与审计记录；倒排表和排序投影只是可重建的派生数据。索引更新应与创建／修订、
删除／恢复、Tag 变化、时间校正、移动及当前 Revision 切换处于同一数据库提交边界：
先验证可索引性和授权，再提交权威变更与派生变更；任一失败则整体回滚。不能在
权威写入成功后异步地让搜索继续以旧投影宣称完整。审计和幂等响应也须指向同一次
成功提交。

启用搜索前，要证明既有写入路径都维护当前投影，或在迁移／重建期间以明确门禁
禁止搜索。每个索引行须对应一个真实、未删除 Page 的准确当前 Revision，不能留
历史行或缺行。索引元数据记录 schema、词元／Unicode／文本提取、排序版本和状态；
打开不兼容、缺失、校验失败或「重建中」的索引时，搜索返回明确不可用，非搜索
读取仍可按其独立安全契约工作。能力发现不能在搜索未就绪时宣称搜索可用。

写路径清单不能只包含新文件集接口：旧 Archive 创建／追加、文件集创建／更新、
Page 删除／恢复、声明时间校正、Tag 关联变化，以及后续的更名／移动、旧版恢复
为新 Revision 都须逐项核对。声明时间或 Tag 变化虽然不生成内容 Revision，却会
改变搜索过滤或排序投影；同内容幂等回放则不应重复产生索引行。若某条写路径尚未
接入维护器，不能启用可用状态；也不能把索引维护失败当作警告后提交权威写入。
搜索读事务应核对所用索引世代仍是已验证的就绪世代，且与本次可见权威内容匹配。

重建从权威数据生成**完整的新世代**，核对 Page／Revision 引用、范围字段、
Tag／时间和行数；采用一致快照加写入追赶，或短暂写入门禁，最终原子切换世代。
不得把部分构建结果暴露给读者。中断后如果旧世代仍与权威数据和代码版本兼容且
同步，可继续使用旧世代；否则搜索失败关闭。重建失败不会回滚或改写权威内容，
也不应悄然丢弃某些大 Page。诊断日志记录失败阶段和对象标识，不记录正文或凭据。

推荐把 `building` 与 `ready` 的世代、权威数据高水位和词元／提取／排序版本显式
记录，在隔离的新世代中构建，校验未删除 Page 的当前 Revision 引用及投影摘要后，
于短事务内原子切换活动世代。若初版选择暂停写入直至完整构建完成，操作门禁及
预计停写成本必须被测量并对用户明示；若选择一致快照加变更追赶，则必须证明追赶
后无缺失、重复或乱序的写入事件。**不能**直接清空活动 FTS 表再逐行重填：其间
的搜索请求会看见空库，失败后也失去可用旧世代。开机检查和异常退出后应只清理
确认未激活的构建残留，不可盲目切换或删除活动世代。索引重建不执行真实业务
数据迁移，也不修改 Revision 历史。

备份和恢复须保留全部权威文件字节与历史 Revision、Tag、声明时间更正、删除状态、
权限、审计及幂等记录；派生索引可以不备份，即使备份了也不得当作恢复权威。
恢复后先验证备份完整性、迁移版本和索引兼容性，再完整重建或验证投影；完成前
搜索不可用。回滚搜索只禁用或移除派生索引和能力，不能删除 Page／Revision 或
重写业务记录。如何在现有备份格式中标记索引世代和运行就绪状态，待迁移设计确认。

现有备份验证按已知迁移版本和 schema 结构核对，因此任何新增 FTS／世代表都须
同步更新备份清单、版本接受范围和验证器，而不是只补 Alembic 迁移。推荐让恢复
目标默认处于搜索不可用状态：先校验权威表和文件字节，再验证或重建派生世代，
完成准确性检查后才开放搜索。可选择把索引文件结构一并备份以加快恢复，但仍要
验证其版本、世代和权威一致性；若舍弃索引，恢复时间和额外磁盘空间应列入演练。
备份旧 schema 的可恢复性与新 schema 的备份／恢复分别做合成测试；不得在尚未
验证回退路径时，对含真实数据的库试跑迁移或恢复。

## 建议的实施门槛与测试矩阵

以下是候选开发顺序，不表示生产迁移已获批准：

1. 审查并接受查询语义、授权桥接、索引候选和版本规则，确认旧接口的兼容路径；
   在此之前只做隔离实验与提案，不合入启用生产索引的迁移。
2. 增加可重建的世代结构、就绪门禁及备份校验；在合成数据库执行升降级、断电／
   中断模拟和历史备份恢复，确认非搜索读取独立可用。
3. 枚举每条已有写路径并将其投影更新纳入同一事务；用注入失败证明权威写入、审计、
   幂等响应和索引同时提交或同时回滚。
4. 完成全量重建、校验和原子切换，然后开放新搜索路由；网页与 Agent 说明仅在
   同一正式能力真正就绪时展示可搜索状态。
5. 运行独立标注的相关性与规模验收，再分别评审合并、发布和实际部署。测试通过
   不自动表示维护者已接受设计，部署也不等于真实资料导入已获验收。

最小自动化矩阵应覆盖：旧 Section Token 不自动扩权，新 Library 授权的读／写
独立性与即时撤销；跨 Library 未授权高相关干扰；宽泛关键词数组的完整 OR 召回、
仅 Tag／仅时间、空查询、单边时间与 UTC 半开边界；汉字一／二／三字、英文数字、
标点与中英混合；单 Markdown、多文本文件、二进制独占 Page 的文件名命中与正文
不误命中；旧 Revision、软删除 Page、同内容重放及恢复；稳定 Top K 与游标在
授权／内容／索引世代变化后的失效；两个 Library 使用相同 Tag ID 时仍准确隔离；
写入、重建、备份恢复的故障注入和失败关闭。
每个集合断言先依据独立的字面判断或人工相关性标签得出预期，不得由被测排名器
自己产生金标准。性能测试不得只跑少量罕见词或只报告中位数。

## 评估与接受门槛

现有[实验脚本](../../scripts/evaluate_fts.py)可复现一次 5,000 Page × 10 KiB 的
合成规模对比；旧提案记录的诊断值为 trigram 新连接查询 p95 约 227 ms、短词召回
11/13，NFKC 应用词元约 142 ms、13/13，NFC 应用词元约 175 ms、13/13。这些
数据来自重复句式，最大查询仅约 1,579 个候选；「新连接」不等于操作系统冷缓存，
测试排序与期望排序还共用一套函数。它们只用于筛掉明显不符的候选，**不能**证明
生产相关性、跨库安全或一秒目标已达成。

新的[搜索 v2 离线评估器](../../scripts/evaluate_search_v2.py)使用词汇更多样的
独立临时 SQLite 数据库，测试关键词 OR、Tag／时间、未授权干扰、当前版本更新及
重建，并以字面扫描核对完整 Page 成员集合。但它仍不使用应用的 Page／授权／
备份表，不测试全部写入路径和原子世代切换；少数人工排序哨兵不能代表真实相关性。
其「新连接」样本也不是操作系统冷缓存，单次运行不能给出稳健尾延迟。离线通过
只能支持进一步选择候选结构，不能被标作生产搜索已实现、已验收或已部署。

开发分支的[可丢弃数据库基准](../../scripts/bench_search_v2.py)已可用
`--include-no-hit` 测另一条无命中查询作对照，并用 `--profile` 查看一次合成查询
的函数耗时。一次本地 5,000 Page × 10 KiB、正文重复同一短语、两个常见短词的
同一临时库连续查询（不是操作系统冷缓存测量）中，
五次查询中位约 3.17 秒；无命中对照约 0.66 秒。剖析显示候选查询的 SQLite
执行占主要时间；无命中对照仍会执行另一条 FTS 查询，不能把 0.66 秒解释成
纯固定开销。去掉中间 SQL 排序的独立试验没有稳定收益，代码已撤回。
这些数据只定位瓶颈，尚未达到约一秒目标，也不满足下述多样语料、尾延迟和
真实服务验收门槛。

后续发现 SQLite 曾在多关键词候选查询中先按 Library 扫文档、再对每行执行
FTS `MATCH`。开发分支把该路径的连接顺序固定为先扫 FTS 命中、再按文档 rowid
查归属；Page 级精确复核、授权过滤和完整候选排序未变。在另一份同样规格的
一次性重复短语数据上连续测三次，查询约为 590、656、575 毫秒，中位约 590
毫秒；无命中约为 94、96、84 毫秒。它验证了这个合成瓶颈的改善，**不是**
真实多样语料、冷缓存、跨 Library 干扰或尾延迟验收，也不证明所有常规查询
都已达到约一秒目标。该测量另加 `--repeats 3 --profile`，并未连接线上数据库。
同样修正单个 1～3 字关键词的候选查询后，另一次 5,000 Page 合成测量中
单词“技术”约为 314、300、363 毫秒；该结果同样只作定位。独立审查进一步
指出：仅改为 FTS-first 会先遍历其他 Library 的命中，再过滤当前 Library，
使窄授权范围受不可见内容体量拖累。开发分支因此给每个索引文档加入 Library
专属候选词，在 FTS 查询中先与关键词相交，之后仍按原始 Library ID 核验；
索引格式版本已变，旧索引必须重建，未重建前搜索失败关闭。这个多库修正已由
定向测试覆盖。加入专属词后在同规格单库合成数据中重测两个常见词，三次约为
583、581、552 毫秒；无命中约为 91、92、104 毫秒。新的跨库延迟、时序影响
和完整容量仍须单独测量，不能从单库数字推断。

上述五次查询的命令为：

```sh
uv run python scripts/bench_search_v2.py --pages 5000 --bytes-per-page 10240 --repeats 5 --keyword 技术 --keyword 报告 --include-no-hit
```

开发分支另增[真实应用矩阵基准](../../scripts/bench_search_v2_matrix.py)，使用临时
合成数据库、实际文件集创建核心、真实 Token 范围检查、索引重建与查询服务。
一次三个 Library 合计 5,000 Page × 10 KiB 的测量中，凭据可读两库共 3,334 Page；
九类查询的返回 Top 20 均与独立字面扫描给出的预期一致，另核验不可见目标拒绝与
一次真实修订后的索引变化。新连接查询约 36～166 ms，三次重复查询最慢约
204 ms，重建约 21.1 秒，修订约 24 ms，主数据库约 159 MiB。
复现命令为 `uv run python scripts/bench_search_v2_matrix.py --scale --repeats 3`。
本矩阵只有单 Markdown、单关键词、等分排序及一个修订样本；初始写入走创建核心，
不是完整 HTTP 写入。它不测操作系统冷缓存、并发、所有写路径、真实相关性或生产
硬件；也不证明返回列表之外的全部候选已由服务返回。它补充跨库、Tag 和时间的
合成性能证据，不替代以下完整验收门槛，也不改变本提案状态。

接受索引结构前，至少使用可再分发且词汇多样的约 5,000 Page × 10 KiB 中英混合
语料，覆盖多个 Library／Section／Book、不同 Tag、单边和双边声明时间、历史
Revision、软删除与多文件文本。测试单字／双字／三字、中英混合、罕见／常见／
无命中词、长关键词数组、仅 Tag、仅时间、组合条件和完全宽泛的已授权范围。
独立标注相关来源和 Top K 预期，不使用被测排序器生成答案；比较精确性、召回、
排序与摘录，加入大量未授权高相关干扰并验证分页及计数不变。

同时记录冷缓存与热缓存查询 p50／p95／p99、最坏样本、CPU／内存峰值、SQLite
查询计划、数据库与索引体积、初建／重建耗时和写入延迟。并发读写、权限撤销、
游标失效、索引更新失败、重建中断和备份恢复必须有故障注入与失败关闭测试。
在明确记录的通用硬件环境上检验正常请求约一秒的目标；对未达目标的常见查询
分析复杂度和优化路径，不靠任意候选截断、人为减小搜索范围或只报告中位数过关。
实验通过、CI 绿色、代码合并、设计 Accepted 和实际部署验收是不同状态。

## 已接受语义及剩余实施选择

表中的跨库默认范围、关键词 OR、固定字段权重、Tag OR、时间筛选和空条件处理
已按上文接受；具体词元／Unicode、权重数值、Tag 身份编码、索引结构和已实现的
游标／错误形式仍须与授权、备份和性能证据一起审查，不能把整篇文档视为 Accepted。

| 事项 | 首版候选及已定边界 | 备选及代价 |
| --- | --- | --- |
| 跨 Library 范围 | 省略 `libraries` 时搜索该凭据实际可读的范围；显式包含无权 ID 则整次请求失败且不泄漏对象是否存在；旧凭据保留 Section 边界 | 强制显式列出所有 Library 较易控制意外大查询，但 Agent／网页调用更繁琐；`write` 是否含 `read` 必须由权限契约另定。 |
| 关键词与 Unicode | NFC→casefold→NFC；数组内 OR，至少一个完整字面项命中；汉字覆盖 1／2／3 连续字，候选后按字段准确复核 | NFKC 会合并更多兼容字符，可能扩大匹配；英文完整词比短子串索引小，但会漏掉用户预期的部分词；标点／表情是否为可检索字面内容仍需固定。 |
| 排序 | 先独立标注评估确定性字段权重与不同关键词命中数，Tag 命中数只在硬筛选后加分，稳定 `(Library ID, Page ID)` 同分 | 仅授权范围的 IDF／BM25 可能改善相关性，但增加范围统计和游标一致性成本；全库统计不可直接用。 |
| 无关键词／空条件 | 有 Tag 或时间时按声明时间降序和稳定 ID 返回 Page；完全空条件交给浏览接口 | 让空搜索也返回确定序列可统一客户端，但会放大意外全库查询和分页负担。 |
| Tag 表达 | `tags_any` 使用 `(library_id, tag_id)` 复合身份且作为 OR 硬筛选；名称解析走独立列举／查询接口，未知、不可见与所选范围外统一安全错误；Tag 名称不参与普通关键词召回 | 直接传名称或裸 Tag ID 较易手填，但改名、大小写规范化、跨 Library 同名／同 ID Tag 会令请求／游标不稳定，甚至错误召回。 |
| 声明时间 | 以已有 Page `occurred_at` 的 UTC 微秒为内部比较单位，公开半开区间并严格校验顺序；默认代填的时间按其实际保存值检索 | 公开毫秒或 ISO 时间更易手填，但须明示精度与转换边界，防止游标和区间遗漏。 |
| 索引与重建 | 先验证应用词元＋FTS5 安全召回＋准确复核，构建新世代后原子切换；恢复后重新验证／构建 | FTS5 trigram 单独覆盖不了短中文；显式倒排表更便于局部统计，存储和写放大可能更高。短暂停写构建较简单但有停机成本；在线追赶更复杂。 |
| 游标与结果 | 游标签名并绑定完整查询、授权范围和版本、排序版本、索引世代及全序键；变更时拒绝旧游标 | 长读快照可减轻失效，但不适合跨 HTTP 请求保持 SQLite 事务；公开总数、分数或高亮需额外隐私与一致性审查。 |
| 保护与错误 | 原始输入、词元数、总工作量及响应大小设公开合理上限；无法完成返回明确失败，不给部分 Top K；日志不含原文 | 很低的候选上限可制造漂亮的延迟数字，却与正常宽泛查询和容量目标冲突。 |

这些剩余技术选择及具体 SQL、迁移、接口兼容、备份与故障测试，是启用生产搜索前
的审查门槛；已接受的查询语义本身不代表这些门槛已通过。
