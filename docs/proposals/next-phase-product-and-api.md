## 2. 内容层级与命名

```text
Library（一个逻辑知识空间，可有多个）
└── Section（长期使用的大类）
    └── Book（一组相关 Page；一本 Book 只有一个 Page 也合法）
        └── Page（一个可独立寻址的内容单元）
            └── Revision（该 Page 在某次写入后的不可变完整快照）
```

一个部署可以容纳多个 Library，例如对话归档和公共资料分别成库；它们共享同一服务和
数据库，因此只是逻辑分隔，不是物理隔离。Section 可表示资料来源或长期主题；Book
可表示一段项目工作、一期视频或一个具体事件；Page 可表示该 Book 中的一篇摘要或
一份资料。**一 Book 一 Page 完全正常**，不能为了满足目录外形强行增加空 Page。
Book 也不必须为每份新 Page 单独创建；管理界面应允许复用现有 Book。

用于展示的 Library、Section、Book 和 Page 名称可以是中文或英文。Page 标题不是
路径或唯一身份；稳定 Page ID 由服务生成，后续更名、移动 Book 或校正声明时间时
仍应保持不变。当前 `page-v1` ID 包含首次创建时的时间和标题派生片段；一旦允许
校正声明时间，ID 中的旧片段只能视为历史标识，检索和排序必须使用可校正的声明时间
字段，不能从 ID 反推当前时间。ID 格式是否改版属于独立兼容性决定。

Tag 是跨层级的多对多标记和检索投影，不替代 Library／Section／Book 归属，也不是
授权边界。现有设计中的 Shelf 是另一种已保存的 Book 视图，不能把 Tag 管理隐式
实现为 Shelf。Tag 和 Shelf 的关联及后者的产品必要性可在后续单独决定。

本开发分支已加入 Tag 的持久化底座：显示名采用 Unicode NFC，匹配键采用
NFC→casefold→NFC，同一 Library 内唯一；关联记录用 Library 与 Page 的准确身份
约束。当前开发分支还提供受保护的 Tag 创建、列举、Page 关联与按 Tag 列 Page
接口。旧凭据仍沿用 Section 授权；显式逐库授权的 Agent 可按目标库独立读／写，
Tag 与关键词、声明时间的组合搜索也已在开发分支接通；这些切片尚未合并或部署。

## 3. Page 是平面多文件内容单元

文件字节继续保存在 SQLite、旧单 Markdown 接口不得静默丢失新格式内容，已经由
[ADR 0004](../decisions/0004-page-file-storage.md)单独确认；本提案中的其他多文件
契约仍待审查。

### 3.1 文件模型

Page 不再被限定为一份 `.md`。其当前 Revision 可以只含一份 Markdown，也可以含
Markdown、图片、JSON、脚本、表格、演示文稿或其他允许的文件；还可以完全没有
Markdown，例如只有一份演示文稿。这里的「文件」是 Page 内容本身，**没有主文件／
附件的父子关系**。Book 管理 Page，Page 管理它的一组文件，Revision 保存某一时刻
这组文件的完整状态。这只是类似小型版本仓库的产品比喻，不要求每个 Page 真正创建
Git 仓库或暴露 Git 命令。

已确认的产品边界是：**所有新客户端使用同一套文件集接口**。单份 Markdown 也是
文件集的一种情况，例如清单中仅有 `content.md`；混合图片或其他文件、以及完全没有
Markdown 的 Page，都走相同的创建、更新、读取、下载和版本机制。不能为单 Markdown
与多文件分别设计两套新的上传语义。

Page 内只有一个平面文件名空间，不接受子目录、绝对路径、`..`、路径分隔符、符号
链接或重名文件。文件名可以使用受支持的 Unicode 字符，但服务必须统一规范化并拒绝
跨平台含糊的名字；原始显示名与规范化键是否分存须由存储提案确定。Markdown 若引用
同一 Page 的图片或其他文件，应使用受约束的相对引用；渲染器只解析当前 Revision
文件清单中的同级文件，绝不借此访问服务器文件系统或其他 Page。跨 Page 引用仍通过
明确的 Page／Revision 引用机制完成。

文件类型不应只凭扩展名判定；响应的 MIME、下载名、内联预览与可执行内容隔离必须
分别设计。最初只需可靠保存、下载和校验允许的文件；视频播放、表格在线编辑、脚本
执行、病毒扫描或内容理解不因「可保存文件」而自动成为已实现能力。单文件、单 Page、
单次请求和整库的大小限制，以及允许的文件类型，需在实施前用真实容量和备份成本
确定并公开。
首版文件下载应以附件形式提供原始字节，不在浏览器中内联执行或渲染上传内容；
管理界面的安全预览与原始下载分离，不能由下载接口的文件扩展名隐式开启。
开发分支现有仅主 Token 会话可访问的稳定 Page／准确历史 Revision 安全预览：
旧层级深路径提供进入按钮，原生选择框可切换同一版本的 Markdown 文件；同层
图片引用只从该 Revision 的文件清单解析。原始 HTML 显示为文字，不内联远程图片、
SVG 或脚本；本地 PNG／JPEG 经验证、完整解码、保留 EXIF 显示方向并剥除元数据
后派生显示，原图仍按原始附件下载。Markdown 1 MiB、图片输入 8 MiB、1600 万
像素和派生输出 16 MiB 是预览预算，不是上传限制；超出预算或纯二进制 Page 仍可
按准确版本下载原始文件。此切片已有合成与隔离真实浏览器测试，尚未完成整体集成
验收、合并或部署，不改变本提案总体状态。
只有文件名、Page 标题及 Page 内明确可安全提取的文字进入首版关键词索引；Tag
仅用于 `tags_any` 筛选，现有 Page 也没有「说明」字段。保存原始
PPTX、图片或视频不等于已经能搜索它们的内部内容。若后续需要 OCR、转录或文档解析，
必须分别定义派生文本、来源、版本和资源预算。

### 3.2 Revision 与同内容写入

每个 Revision 是该 Page 文件清单和各文件字节的不可变完整快照。新增、删除、改名
或更改其中任何文件都会形成新的内容快照；恢复旧版本是创建一个内容等于旧快照的
**新** Revision，而不是改写历史指针。实现可在内部对相同文件字节去重存储，但对外
仍必须能按 Revision 准确还原整组文件。二进制数据、文件清单、当前指针、派生索引、
审计和成功幂等记录的提交边界应作为一个事务设计，不能返回成功后缺失某个文件。
如果选择恢复的旧快照与当前快照完全相同，则返回「内容未变化」，不另建 Revision；
只有实际把当前内容改回旧快照时，才通过新 Revision 记录这次恢复。

内容相同的判定不能仅比较某一份 Markdown 的哈希。多文件 Page 应比较规范化的
文件名集合及每个文件的内容哈希；同一组文件名和字节再次提交到**同一个 Page**时，
返回明确的「内容未变化」结果和当前准确引用，不新增 Revision。同样的字节上传到
另一个 Book 或另一个 Page 是独立内容，不能用全库哈希合并。标题、Tag、来源或声明
时间等元数据如果变化，应作为可审计的元数据修改处理；正文未变本身不应凭空制造
一个内容 Revision。具体哈希规范、编码、校验和错误码需要公开接口提案固定。
开发分支已实现仅主 Token 管理会话使用的 Page 标题编辑，并用不可变标题事件
保留历史标题，供旧响应与备份验证还原；这不是 Agent 元数据写入接口，尚未合并
或部署。该实现不改变本提案的 Proposed 状态，也不预先决定公开接口契约。
统一文件集接口的每次内容写入都提交**整组**同级文件；文件集实际变化时，整组共同
形成一个新 Revision，而不是逐文件产生多个版本。创建请求需要幂等键，更新请求
需要当前 Page 的强 `If-Match` 条件；两者的重试身份、响应和错误细节仍须在公开接口
契约中确定。

### 3.3 写入、读取与本地文件

Agent 可先将准备上传的正文和其他文件写入本机，再调用标准 HTTP 接口；不要求用户
事先逐篇预览，也不要求为每个 Page 生成一套额外的「待上传包」。接口应明确选择目标
Library、Section 和 Book，区分「新建 Page」与「更新既有 Page」。更新优先使用服务
返回并可在本地记下的 Page ID 和当前 Revision／ETag；标题或本地路径不能作为唯一
身份。找不到本地记录时可以进行受权限约束的搜索和人工消歧，不得猜测目标 Page。

一次上传在结果丢失后重试，必须重放同一幂等身份和完全相同的目标、元数据、文件
清单及文件字节；改变任何一项都应开始新操作。成功响应后，Agent 应读取**本次目标
Page 的准确 Revision**并核对文件清单和哈希。全库找到相同哈希只证明某处有相同
字节，不证明本次 Page 上传成功。只有 Agent 为这次上传新建的临时本地副本才能在
成功核验后清理；用户原本已有的源文件绝不自动删除。保存 Page ID 的轻量本地映射
可以提高后续更新可靠性，但不应成为访问服务的强制前提。

现有 Archive 专用 `metadata`＋`content` 上传接口和客户端仍应在过渡期保持可用，
作为旧客户端兼容路径，而不是新客户端的第二套单 Markdown 接口。新客户端统一使用
文件集协议，即使只上传 `content.md` 也不改走旧接口。旧单 Markdown 修订接口遇到
当前文件集无法完整表达的 Page，必须明确拒绝改写，不能把其他文件静默丢弃；
具体 409 错误契约仍待审查。统一协议可以使用与旧 Archive 不同的路由来保持兼容，
但新协议内部不按文件数量分叉。新 URL、传输格式、大小配额、原子性实现、旧 Page
映射及回退路径仍需专门的接口与迁移审查，本文不将其定为已接受的 HTTP 契约。
当前候选路径、multipart 形状和开放问题详见[统一文件集 HTTP v1 草案](unified-file-set-http-v1.md)。

本开发分支已具备统一文件集的内部新建、整组修订、历史读取、备份校验，以及共用的
有界 multipart 解析器；读写路由已注册到开发分支应用。合成 HTTP 测试将单 Markdown、
多文件和仅二进制内容都送入同一格式并按准确 Revision 回读。这些行为不是已接受的
公开契约，也不表示已合并或部署。正式开放前仍需完成读写契约与整体验收。
当前逐 Library 的 `read`、`write` 独立，写权限不包含读取；写后准确回读需另具
读取权限。旧 Section 凭据保持原授权语义，不会因新接口自动扩权。

## 4. 声明时间、服务器时间与软删除

Page 的**声明发生时间**表示内容实际对应的工作、事件或资料时间，不等于服务器接收
时间，也不等于最后修改时间。搜索的时间过滤默认使用声明发生时间。另保留服务器
创建和更新时间用于审计、排序备选项及排障。上传时提供有效声明时间应原样保存；
缺失时可以服务器当前 UTC 时间代填，同时在结构化响应中明确标注代填来源和警告，
提醒调用方可再校正。**提供了但格式或取值无效的时间应拒绝并要求修正**，不能静默
用当前时间污染历史排序。服务端还应提供受授权保护的声明时间校正操作，记录旧值、
新值和操作者；校正后不改变稳定 Page ID 或已有 Revision 正文。
旧 `page-v1` 存储校验要求 ID 中的初始时间分量与 `occurred_at` 一致。本开发分支
已经在存储层解耦「不可变的初始 ID 时间分量」与「可更正的声明时间」，并增加更正
审计及备份校验；受授权保护的公开更正接口也已在本开发分支实现，详见
[Page 版本与历史](../03-page-revision-and-history.md)。创建 Archive Page 的缺省时间
代填及创建响应中的结构化警告也已在本开发分支实现；普通读取不另存代填来源。这些
切片不代表本提案已获接受、分支已合并或服务已部署。

### 开发分支的主会话声明时间校正

管理者从当前 Page 预览提交必填的带时区 RFC 3339 时间，以及该页面的当前强 ETag。
管理路径为完整 Library／Section／Book／Page 下的 `POST .../occurrence`；只接受
当前主会话，同源与 CSRF 校验保持不变，不要求另填 operator Token。缺少或无效的
时间返回 422，旧 ETag 返回 412，错层级或已删除 Page 返回 404。历史版本预览不
提供编辑表单。新时间相同则成功提示无变化，不新增校正记录或内容活动。

校正在单个短写事务中复核主会话代次、路径、未删除状态和 ETag；写入旧值、新值、
实际主审计身份与单调递增的服务器操作时间，并同步当前版本搜索索引。索引、审计或
校正任何一项失败，都不能部分提交。只调整声明时间和页面更新时间，不改 Page ID、
UID、标题、版本编号或文件字节；初始 ID 中的旧时间片段仍是历史标识。

`0027` 将原有校正记录／临时 guard 扩展为两种互斥归属：旧 Agent 的 Caller 与
所属库，或真实主会话审计 ID。不能为管理者创建伪 Agent。旧 Agent 行逐列保留，
校正历史仍不可改删，临时 guard 必须完整消耗。新增主校正审计与校正记录逐一对应，
动作、目标和服务器操作时间必须一致；产生主校正历史后拒绝降级到无法表示它的
`0026`。只有旧 Agent 历史的数据库允许无损回退。

备份对 `0026` 与 `0027` 分别检查原格式、历史、审计关系及文件集成功回执；恢复
仍保持备份原版本，不自动升级或重签 Token。原先成功上传的回执不会因时间更正被
改写，重试返回当时的准确版本和 ETag，不覆盖现在的声明时间。首页增加管理者的
时间更正活动，身份详情不混入它；搜索与 Book 排序使用更正后的声明时间。

该切片仍是开发分支实现与合成验收范围，未合并、未部署，不改变本提案总体状态。

时间筛选应允许只给起点、只给终点或两者都给，而不是要求调用方填写「极大时间」。
建议定义 UTC 半开区间 `[起点, 终点)`；公开 API 的数字时间戳单位须在接口提案中
精确指定，并在浏览器侧做时区转换。跨时区输入、边界值及代填时间都需要测试。

普通删除以 Page 为单位进入回收站：默认列表、读取和搜索不再返回该 Page，但其全部
历史 Revision 和文件仍随 Page 保留。恢复后恢复同一个 Page 身份、历史与引用；
误删不依赖人工直接修改数据库。后续可以提供独立、严格授权的永久清除流程，但它
不是普通删除，也不能假定备份立刻同步清除。Agent 持有相应写权限时可执行普通创建、
修改、移动和软删除，不设置每次写入都到网页批准的工作流；所有成功变更必须审计。

## 5. 单人管理入口、设备 Token 与授权

管理后台只面向一个维护者。主 Token 登录不要求传统用户名；管理身份和普通
Agent／设备身份分开，主 Token 不在普通内容 API 中代替设备 Token。

**旧版兼容路径：**旧网页登录密码只建立旧管理会话，旧签发／吊销表单另需 operator
Token。已合并实现仅在数据库尚未设置主身份时保留这条路径；安装新镜像或执行数据库
迁移本身不会自动创建主 Token，也不会暗中替换管理员保存的登录值。

**新的主身份路径：**首次设置后，同一个主 Token 用于登录并授权本期管理操作，签发、
授权编辑、轮换及撤销逐库 Agent 凭据均不要求再填 operator Token。主 Token 只存
不可逆校验值，管理写操作使用真实主身份审计和事务内会话代次复核。首次设置成功
立即关闭旧密码／v1 会话登录；已有 Agent／operator 凭据不因此失效或扩大权限。
旧 Section 凭据保持原语义，转换为逐库授权须显式签发，不做隐式迁移。
尤其不能仅以「数据库尚无管理 Token」为条件向任意远端浏览器开放首次注册：若服务
已经有公开入口，未经保护的初始化页会被抢先占用。首次设置必须有本机操作、一次性
带外证明或等效的部署侧限制；已实现的方式如下。新登录保留短期
HttpOnly、SameSite 会话 Cookie、同源检查和 CSRF 防护，不把管理 Token 放进 Cookie；
管理 Token 轮换或本机恢复后，还须让既有会话及时失效，不能只等 Cookie 自然到期。
当前管理会话使用独立的签名材料；管理 Token 的数据库校验值不能充当 Cookie
签名密钥，否则只取得数据库副本的人也可能伪造管理会话。当前实现继续使用独立
的会话签名材料，并在逐请求及管理写事务中核验主身份代次；轮换后的旧会话失效已有测试。

开发分支已接通 `GET/POST /admin/master/setup`：已有有效旧密码会话与 CSRF 可设置
主身份；新安装可使用独立配置的 `PATCHOULI_ADMIN_SETUP_TOKEN`，必须为 32 至
1024 UTF-8 字节且不同于会话签名材料。没有这两种授权时首次网页设置关闭。
设置页的专用 Cookie 有 5 分钟有效期、独立签名用途与 CSRF；它不授予普通管理
访问，不含设置凭据或主 Token，也不替代同源检查。在 `BEGIN IMMEDIATE` 中复核
当前结构、主身份仍为空、原始 Cookie 与设置授权，身份和脱敏初始化审计同事务
写入；重复与并发请求不能覆盖身份。成功切换到主 v2 会话并关闭旧密码／v1 登录，
不改变 Agent／operator 凭据。原 `/admin/setup` 的结构初始化语义保留，轮换及遗失
恢复保持本机流程；不新增迁移。此开发切片不改变提案状态，未合并或部署。

管理后台可创建、命名、描述、查看、轮换和吊销 Agent／设备身份。每个身份默认
一份活动 Token；界面默认仅显示首尾各约四个字符，点击眼睛可受保护地显示完整值，
点击复制可再次取得该值。未请求显示时，普通详情页不应预埋完整 Token；显示和复制
要求有效主会话、同源与 CSRF 校验、当前凭据有效及事务内主身份代次复核；首版不另弹
一次主 Token 输入框，但会留下不含凭据的审计记录。响应必须禁止缓存；明文不应进入
URL、日志、受跟踪配置、
管理会话或浏览器持久存储。浏览器自身的密码保存能力可以由使用者选择，但不应作为
服务端保存或恢复 Token 的方案；如需少量自有脚本实现眼睛和复制，也应保持严格的
内容安全策略，不引入第三方脚本或宽松的内联脚本例外。

既有已签发凭据只存不可逆校验值、只在签发时显示一次。为满足重复显示且保持单机迁移
简单，新的产品取舍是：**管理 Token 仍只存不可逆校验值；新签发的 Agent／设备
Token 明文保存在 SQLite 的独立受限存储中**。普通凭据模型、列表和管理详情不得
顺带加载或返回明文；只有受保护的单独显示／复制操作可读取它。明文不得进入 URL、
日志、审计、公开配置或普通内容 API。此方案不另设数据库外的解密钥匙，但并不提供
静态数据保密：数据库文件、WAL、备份或旧快照被复制时，持有者可离线取得其中的
活动 Agent Token，网页鉴权无法阻止。数据库及其每份备份因此都必须按机密管理；
备份恢复后的旧凭据可能重新变为有效，不能只靠恢复流程假定吊销状态仍成立。
旧备份恢复后先在隔离状态核对凭据状态，通过验证后再开放入口。维护者已选择完整
恢复备份当时的状态，包括备份后吊销的撤销；不增加外部安全代次，也不强制重新签发
全部 Token。存储表、访问控制及合成恢复行为已有实现和独立审查；本次现场机密材料
权限已核验，未来正式恢复操作仍须独立验证，不能以网页鉴权代替文件权限。
明文显示接口使用 POST，只在管理会话有效、同源与 CSRF 校验通过、该凭据仍有效时
返回当前活动值，并禁止响应缓存；
默认页面只显示掩码，不预先把明文写进 HTML 或浏览器持久存储。吊销或轮换须停止
当前值的显示，但不能据此声称历史 WAL、备份或快照中的副本已经清除。
既有 Token 因从未存储可恢复明文，迁移后也无法「补出」完整值；需保持旧 Token
直到正常到期／吊销，或让管理员显式签发新格式。可重复复制不等于永不过期；到期、
轮换和吊销仍清晰展示。新建身份默认签发一枚 Token；兼容数据中可以保留多枚凭据，
不因升级而批量吊销。界面的轮换针对选定的活动逐库凭据，原样保留其授权并使旧值
失效；旧 Section 凭据不通过这条入口自动变为逐库授权。

## 6. 管理后台信息架构

界面优先复用常见、易理解且支持键盘操作的导航、卡片、列表、表单、详情展开等标准组件。
延续现有服务端渲染和本地静态资源；只有确有交互需求时才增加少量客户端代码，
并保持移动端可用和严格的内容安全策略。如确需组件库，优先成熟常用、可本地打包
且不要求放宽安全策略的方案，不为外观引入不必要的远程依赖。

左侧导航面向日常管理，而不是部署运维：

1. **主页／近况**：按时间展示内容活动。每行说明哪个身份在何时创建、修改、移动、
   删除或恢复了哪一个 Page；身份链接进入对应设备详情，Page 链接进入当前预览或
   指定 Revision。相对时间的悬停信息显示完整绝对时间。
2. **知识库**：自适应网格展示 Library 名称、简介、创建时间及可见内容数量。进入
   Library 后按 Section、Book、Page 浏览；允许一本 Book 只有一个 Page。支持建立
   结构、查看文件清单、预览可安全渲染的类型及浏览历史。
3. **Tag**：列出 Tag、关联 Page 数量和相关内容，允许创建与维护关联。Tag 是筛选
   标签，不决定授权或唯一归属。
4. **设备与 Token**：创建身份、设置各 Library 读／写、查看最近活动和 API 请求、
   掩码／显示／复制／轮换／吊销 Token。
5. **接口与 Agent 指南**：只读展示当前 API 能力、示例响应、Skill、MCP 和内置
   指令文本；这些开发者维护的说明不能在管理页面任意改写。
6. **搜索**：为人类提供关键词、Tag、时间和 Library 选择，与 Agent 使用同一底层
   搜索语义；结果按 Page 展示，可进入预览与准确 Revision。
7. **回收站与请求记录**：浏览和恢复已软删除 Page；另按身份、接口、结果及时间查看
   受保护的 API 请求元数据。

内容活动与 API 请求是不同视角：一次成功写入对应一次可追溯的内容变更；一次普通
读取、搜索、拒绝或失败请求也可有请求记录，但不会伪装成内容变更。请求记录应包含
请求 ID、身份、接口类别、状态、耗时和时间等必要元数据，不得存原始 Authorization、
完整正文、搜索词、原始路径／查询串或接入 Token。已确定对到达应用的 API 成功与
失败请求不采样，在线库保留 30 天并自动清理；仅主 Token 会话可查看，首版不导出。
代理在请求到达应用前拒绝、服务停机或数据库不可写时，不能声称已持久记录；历史
整库备份的保留周期另按备份政策核对。首页不应把网络请求洪流混入内容时间线。

开发分支的近况时间线已读取成功的旧 Archive、统一文件集，以及 Agent／Operator／
主会话 Tag 内容事件。跨知识库
写入时，操作者链接使用身份所属 Library，内容链接使用目标 Library；文件集修订链接
指向对应 Revision。开发分支另以独立的 0023 表记录到达应用的 API 请求结果，
按请求开始时间展示 20 条一页的全局和按身份记录，并在后台定时清理超过 30 天的
在线记录；只保存路由模板、状态、耗时、请求 ID 和已验证的身份标识，不保存原始
路径、查询词或凭据。持久化失败不会改变业务响应，但该次记录可能缺失。上述能力
已通过本地测试，PR 尚未合并，服务也未部署；不能据此宣称代理侧拒绝的请求已记录。
开发分支的 Caller 详情也可按身份查看最近成功内容事件；此视图不混入主账号操作或
普通 API 请求。首页和 Caller 详情现可按每页 20 条继续查看更早的内容活动；
新增审计索引只加快这一读取，不构成搜索索引或搜索功能。分页仍未合并或部署。
开发分支的 Book 详情 Page 列表也按每页 20 条有界读取；旧的内部 Book 读取
语义保留。分页是实时列表：锚点 Page 已删除或排序时间改变时拒绝旧游标，其他
Page 在跨请求期间变动则不承诺冻结快照。这不代表整个知识库管理界面已验收，
亦尚未合并或部署。

当前管理后台不是主机 Shell、Docker 或镜像控制台。增加内容浏览和 Token 页面不应
顺手加入部署、数据库原始查询或任意代码执行能力。

## 7. AI 原生接入与标准 HTTP

管理页面提供一个任何人可阅读和复制的**无密钥接入指令**，可按实际选择的入口生成
正确服务根地址；公开仓库和示例不得写入维护者私有域名、主机或网络拓扑。指令只
负责引导本地 Agent：若无设备 Token，请用户在管理后台创建或复制；随后由 Agent
展示适用于本机系统的交互式输入方法，让用户在本机终端或受保护的本地机密存储中
填写。**不得要求用户把 Token 发到模型聊天、提示词或远端模型 API，也不得把它作为
Shell 命令行参数写进历史记录。**「一键复制 Token」是页面上的独立受保护动作，
不是把 Token 嵌入公开指令。

持有 Token 后，Agent 先调用身份与能力接口，确认实际身份和权限，再访问需要
Token 的 Skill 下载入口，下载 `SKILL.md` 与清单列出的其他文件，核对版本和摘要，
安装到当前 Agent 环境支持的位置。下载地址必须稳定、可配置，不能假定 `/docs`
下已经存在 Skill 文件；更新时比对远端版本与本地修改，不静默覆盖本地定制。公开
指令应包含足够的引导，但受保护 Skill 不得包含真实 Token。未经鉴权的访问不应
泄露私有内容。不同 Agent 产品的 Skill 放置路径和安装机制可以不同，不强迫一种
具体客户端布局。

首选操作方式为标准 HTTP：Skill 解释鉴权、获授权库的层级发现、准确读取、准备本地文件、
文件集上传、幂等重试、版本条件、写后验证和错误处理；搜索索引未就绪时明确
报告不可用。开发分支的 Section／Book 两个列表允许可选 `library_id`，省略保持
身份归属库，指定时要求精确凭据对目标库有读权限；仅写权限不包含读取，旧 Section
模式不可借此跨库。游标绑定目标库及精确凭据，每一页重新检查当前授权；升级前的
这两类游标需重新开始分页。列表响应字段和分页上限不变。Bash、PowerShell 的本机交互
输入与 Python 标准库调用示例不把内容和 Token 拼进命令行参数。已有 CLI 与 MCP
可以继续维护兼容，但下载 Skill 和使用知识库均不以安装它们为前提。开发分支的
打包 Skill 已改为 HTTP 优先、旧 Archive 仅兼容，并说明统一文件集契约；已用合成
应用测试验证下载摘要与多文件准确回读，尚未合并、部署或逐设备验收。

开发分支另提供 `GET /api/v1/libraries/{library_id}/sections/{section_id}/pages`
与 `GET /api/v1/libraries/{library_id}/pages/{page_id}`。前者按目标库、Section 和
当前凭据分页，后者从稳定 Page ID 返回当前归属与文件清单链接，便于移动后重新定位。
两入口仅在配置检索游标签名密钥、`capabilities.features` 包含 `retrieval` 时注册；
只有搜索或文件集能力不代表这两个入口可用，未注册时的 404 不能推断 Page 是否存在。
两者在读取事务内重新核对凭据及目标库读权限；仅写授权不够，旧 Section 模式不能
借此跨库，未授权目标与已删除内容返回不可用，不提供跨库存在性探测。旧读取路由保持
原语义；标准 HTTP 接入可使用新入口，现有 SDK／CLI／MCP 的层级发现仍须分别核对。

## 8. 当前 Revision 的真实搜索

搜索必须是真实可用的功能，不能以模拟界面或静态示例替代。第一阶段不依赖向量
数据库、外部模型或语言词典，采用可重建的字符／词元倒排索引作为候选召回基础。
中文至少覆盖单字、双字和三字连续片段，英文和数字需要明确规范化。全文只索引每个
未删除 Page 的当前 Revision，历史内容仍由明确历史接口访问。索引属于派生状态，
创建、修订、删除、恢复、改 Tag 或校正时间时，应与权威内容保持一致或明确失败关闭。

查询输入以结构化字段表达，不接收用户拼接的 FTS／SQL 语法：

- `keywords`：零到多项字面字符串，任一项在同一字段连续命中即可召回，
  匹配更多项可提高排名；不做模糊纠错，也不要求所有项都出现。人类界面用空格
  拆分已明确分开的词，不强迫中文用户先分词。
- `tags_any`：零到多项已存在的 Tag。非空时 Page 至少包含其中一个；命中多个可
  给予额外权重。指定 Tag 无效时返回明确错误或建议，不静默忽略。
- `occurred_from`／`occurred_before`：可单独使用的 UTC 声明时间范围，不填即
  不限制；不要求虚构一个「无限大」时间值。
- `libraries`：可选一个或多个已授权 Library；省略时搜索该凭据实际可读的全部
  Library，旧 Section grant 不因此扩权；结果不能泄露其他 Library 的计数、排序
  影响或摘要。
- `limit`／游标：返回 Top K Page，含标题、归属、命中解释、准确当前 Revision 引用
  和供人预览的安全摘要；取完整文件需另行按 Page／Revision 请求。

没有关键词但有 Tag 或时间条件时仍可检索；完全空条件不执行搜索，人类界面引导
到浏览页，接口明确提示使用浏览接口。首版使用固定字段权重；具体权重数值、
同分决胜和分页一致性的开发实现见下文，排序质量仍须通过语料评估。Tag 名称不参与
关键词召回，Tag OR 与声明时间的 UTC 区间是硬筛选。服务器可自行选择先利用倒排
索引、Tag 索引还是时间索引；「先授权
与筛选，再排序」是结果语义，不是要求 SQL 固定执行顺序。Tag 列举、Tag 下 Page
列表及 Tag 管理同时提供给网页和 Agent。

开发分支的搜索请求支持可选不透明 `cursor`，响应提供 `next_cursor` 与每项可空的
`snippet`。续页必须原样保留查询条件和 `limit`，通过 POST 正文提交，不放入 URL。
每页在同一读取事务内重新鉴权、计算完整排序，并核对绑定的精确凭据或主会话代次、
当前授权、查询、索引代次和可见结果指纹；关联条件或可见结果改变时返回
`400 invalid_cursor`，客户端应明确提示并重新搜索，不能悄悄从首页重来。这不是跨请求
持有的数据库快照，也没有缓存整份结果；每页仍承担完整查询和排序成本，性能须重新测量。
生产配置使用已有的 `PATCHOULI_RETRIEVAL_CURSOR_SIGNING_SECRET`；未配置该值的开发
环境只返回首批结果，不提供续页，提交游标会被明确拒绝。

摘录包含 `file_name`、`text` 与 `matched`，至多 240 个 Unicode 字符，来自当前准确
Revision 的已授权文本投影；纯二进制 Page 可为 `null`。投影经过 NFC／casefold
规范化，因此摘录仅供定位，不代表原始大小写或逐字引文；取原文应使用准确版本文件
接口。网页将摘录作为纯文本转义，不执行其中的 Markdown 或 HTML。

旧 FTS 提案中的每 Section 最多 1,024 篇、候选最多 256 项会拒绝正常的大范围或
高频词查询，而且旧查询把词元全部按 AND 组合；这些都与本阶段预期的数千篇内容和
关键词数组相关性排序不一致，因此**不能原样接受或实施**。应修订
索引表示、候选召回与排序路径，在约 5,000 篇、每篇约 10 KiB 的合成内容
上记录索引构建、更新、常见／罕见／无命中词、Tag 和时间组合、并发
与数据库体积。正常查询约一秒是性能目标，不是靠任意截断候选或阻止常见查询制造
出的假指标。仍需对异常巨大的原始请求、单项长度、响应数量与总工作量设置合理保护；
超限或超时必须显式报错，不返回看似完整的部分结果。首版的固定字段权重须由独立
标注的代表性语料评估来进一步调优，但依据 2026-10-03 维护者决定，本期先按
常规查询目标验收当前确定性实现，不以尚未建立的大规模人工 benchmark 阻塞交付。
操作系统冷缓存及其他增强评估也留待后续；独立正确性、权限、分页和恢复检查不取消。

1. 已接受上面的可观察查询语义；继续确定索引和接口剩余细节、修订冲突的旧 FTS
   提案并独立审查，再以迁移、备份、重建和性能测试作为生产启用门槛。
2. 先增加向后兼容的存储结构、备份与数据迁移验证；现有单 Markdown Page 必须可
   映射为仅含一文件的多文件 Page，旧客户端不能被无提示地破坏。
3. 再完成多 Library 权限、Tag、Page 文件快照、时间校正、软删除／恢复和非搜索
   读取，随后上线真正的倒排检索与性能回归。
4. 管理后台与 Agent Skill 只调用已实现且已测试的接口；界面不可先展示尚不存在的
   创建、搜索、恢复或重复取回 Token 功能。新增操作需覆盖权限、并发、幂等、回读、
   隐私、迁移和回退测试。
5. 使用合成数据完成跨系统 AI 接入和约定规模搜索测试；真实内容导入、真实备份
   恢复和私有部署属于单独授权的运维步骤，不由文档提交自动触发。

逐设备验收应分步记录实际入口可达性、Token 身份与 Library 权限、Skill 下载和
安装、读取、搜索、上传及写后准确回读，而不是只凭登录页打开就宣告接入完成。
真实资料清点和导入不属于本轮验收，须在后续获得另行授权后执行，不作为本期
合成交付的强制门槛。获授权的分散资料导入先只读清点来源、格式、时间和重复项，确定 Library／Section／Book
归属，再用少量非敏感样本试导入并核对 Page ID、Revision、文件清单、哈希和搜索
结果。设备名单、私有地址、资料路径、凭据和测试正文留在私有验收记录，不写入
公开仓库；任何真实资料导入仍须另行授权。
