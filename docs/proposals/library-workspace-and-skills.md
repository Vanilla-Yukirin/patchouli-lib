# 知识库工作区与库内 Skills 产品需求

- 状态：产品需求已确认（Accepted direction）；数据模型、HTTP 与迁移方案仍待设计审查。
- 实施状态：待原型与实现。本文不表示现有网页、Agent 接口已提供全部能力。
- 范围：知识库概览、分区阅读、文本编辑、附件引用、库内 Skills 及本机安装更新。
- 交付方式：前端迁移、文本编辑、引用调整与库内 Skills 在同一轮开发中交付，内部
  按依赖顺序推进（见[迁移计划](admin-frontend-migration.md#阶段)）；每项仍须先
  定契约再实现。

本轮以阅读、检索和配置管理为主要场景，同时保留准确修改文本和附件的人工入口。
知识库初建时方便设置 README、Skills 与接入规则，日常使用时方便找内容、阅读和
归档。管理操作不应淹没正文，也不应要求用户理解内部操作键、ETag 或文件摘要。

本文细化并更新[管理前端交互规范](admin-frontend-interaction.md)中的产品行为。
[三层 README 与 Agent 结构管理](library-guides-and-agent-structure.md)继续定义已有
结构能力；新增库内 Skill 的实体与接口不能仅靠前端改名视为已经实现。

## 导航与页面分层

### 全局导航

全局功能只在顶部出现一次，包括知识库、搜索、标签、回收站、凭据管理、设置及
接入帮助。入口可以分组、折叠或放入更多菜单，不在左侧重复同一份全局导航。
语言选择在页面切换和提交后保持一致。

左侧空间用于当前内容的目录，而不是另一套全局菜单。页面仍有可分享的 URL、
前进后退与直接访问能力，常规操作和文档切换局部更新，不依赖整页刷新。

### 知识库概览

进入知识库先显示概览，不自动跳过概览去恢复上次文档：

1. 顶部显示知识库名称和简短描述。
2. README 使用说明、相关 Skills 分成明确板块，各有标题、入口和操作。
3. 下方平铺该库的分区，显示分区用途并提供进入入口。

README 可摘要显示并展开全文；Skills 展示名称、用途和当前版本，链接可直接打开
详情。板块通过背景、间距、边界和文字层级区分，不将所有信息连续平铺成同一层。
空库提供 README、Skills 和结构设置的引导，不要求先建立占位分区或书籍。

### 分区阅读工作区

进入分区后，左侧展示可折叠的书籍与页面树，右侧阅读所选文档。选择书籍、页面
不要求逐层进入另一张管理表单页。分区和书籍的用途、README 仍可查看和编辑。

可在分区范围记住目录展开、最后阅读页面和位置；这只是轻量界面状态，不保存正文、
凭据或全局阅读轨迹，也不改变知识库入口先看概览的行为。是否首版恢复阅读位置
属于原型细节，不作为核心功能的前置条件。

## 默认阅读与入口文件

点击 Page 默认进入内容阅读，正文渲染与文件选择在同一工作区完成，不再要求从
普通详情另跳一层“安全预览”。附件、历史、属性和管理操作使用明确的次级区域；
SHA-256、原始字节数及内部 ID 默认折叠，仍可查看、复制或下载。

Markdown 的渲染在浏览器前端完成，阅读与编辑预览使用同一个渲染器，规则见
[迁移计划](admin-frontend-migration.md#markdown-渲染与标题契约)。

### 入口文件

每个文档版本有一个明确的**入口文件**（接口字段暂称 `primary_file`）：它是默认
阅读的文件，也是展示标题的来源。入口文件在写入文件集时确定，并随该版本保存
（暂定为版本属性而非页面可变设置，见总览开放问题）。

1. 网页创建与保存时总有入口文件：默认选中第一个可预览文本文件，用户可更改。
2. Agent 写入可以不指定入口文件。服务端接受写入，不拒绝，但在响应中给出明确提示，
   要求调用方指定入口文件。
3. 已有新版展示记录但未选入口的版本显示“无入口文件”，列出文件并提供“设为入口文件”。
4. 缺少新版展示记录的旧归档在管理阅读时兼容：唯一 Markdown（可带附件）或唯一
   README 自动打开；歧义不猜。只读推导不写入数据库、不新增版本，不要求逐篇设置。
5. 入口文件必须存在于该版本中，且能安全预览。

普通文件的预览能力不由是否恰好命名为 `content.md` 或 `README.md` 决定。HTML 也不能
作为可信脚本执行；安全预览或源码查看方式沿用既有内容安全边界。

Skill 固定以根目录的 `SKILL.md` 为入口，其余文件放在该 Skill 的文件树中。

## 展示标题与文件名

新版展示标题在**写入时**确定并随版本保存；旧归档的管理阅读例外见
[ADR 0005 补充](../decisions/0005-library-workspace.md)：

- 写入文件集（含 Agent 写入）时，服务端取该版本入口文件的第一个一级标题，保存为
  该版本的标题；列表、搜索与阅读读取已保存的标题，不为展示标题重新解析正文。
- 提取不到标题时，标题就是“无标题”：没有一级标题、入口文件不是 Markdown、或没有
  入口文件。不回退为文件名，也不要求同时维护独立网页标题。
- 历史版本使用该版本自己保存的标题，不用当前标题冒充，也不因解析规则变化而变化。
- 界面保留弱化的 `#` 标识，说明标题来自正文，文件名以次级文字另行显示。
- 标题变化不自动重命名原文件，也不改变稳定 Page ID、引用地址或所属关系。

“第一个一级标题”的判定遵循 CommonMark：ATX（`# 标题`）与 Setext（下划线 `===`）
均计入；代码块、HTML 块中的内容与文件开头 front matter 不计入。写入端（Python）
与编辑预览（前端）必须使用同一组共享测试向量，避免规则分叉。

编辑预览可即时反映标题变化，保存后线上标题与预览一致。

已有独立 Page 标题的去向——Agent 创建页面时的必填 `title` 字段、网页“编辑 Page
标题”、搜索投影的更新——尚未确定，见总览开放问题；不能借此重算既有标识符或
丢弃历史元数据。

## 人工编辑与保存

能识别为文本的文件提供编辑按钮，包括 Markdown、JSON、脚本和其他文本；不局限
于当前入口文件。二进制原件不提供文本编辑，但可下载、替换或上传附件。

桌面使用源码与实时预览左右分栏；不适合内容预览的文本至少支持源码编辑。
窄屏用编辑与预览切换实现同等功能，不强塞两栏。

- 编辑中的输入保留在当前前端页面内，点击“保存”才提交正式修改。
- 不自动保存正式版本，不建立服务端草稿、浏览器持久草稿或跨设备续写系统。
- 离开有未保存修改的编辑区时，给予简单提醒。
- 只修改某个文件时，保留其他未改动的附件；替换整个文件组是明确的高级操作。
- 有效内容修改保存为一个完整的新版本，既有历史保持不可变；无内容变化不制造空版本。
- **保存冲突时直接覆盖**：网页保存不因文档已有更新版本而拒绝；用户保存的内容成为
  新的最新版本，被取代的版本保留在历史中，成功提示说明这一点。不建设差异合并界面。
  Agent 公开 API 既有的并发契约不变。

正文与附件支持上传、修改、替换和插入引用。文本编辑仍是原文件集修订，不另建
一套脱离 Page、Revision 和原始文件的正文存储。

## 附件改名与引用批量调整

附件改名后，先分析当前 Page 或 Skill 文件集内能明确识别的 Markdown 引用，
展示修改窗口，再由用户应用：

1. 按文件分组列出命中位置、行号、列号及上下文，突出实际链接目标。
2. 展示修改前后对照，能确定的修改默认全选，允许逐项取消或全选。
3. 未勾选的引用若可能失效，保留醒目提醒；无法可靠分析的引用单独提示，不伪装
   成可以自动修复的命中。
4. 点击“应用”后批量调整编辑区，最终“保存”时将改名与所选引用作为一个版本提交。

扫描对象包括能识别的 Markdown 链接、图片引用和引用式链接；具体语法与位置计量
在解析契约中确定。共享引用定义须说明影响位置，不能让用户误判勾选的修改范围。
不对脚本、代码块或普通文字做同名字符串的盲目替换，不修改历史版本，也不自动
跨其他 Page 或知识库改写内容。跨文件的建议须绑定正在编辑的版本和内容，编辑后
不能把旧位置直接套到新文本。

该功能是本轮交付的必要能力，不降级为仅提醒。开发顺序排在基础文本编辑与保存稳定
之后，这只是工程先后，不改变其重要性。

## 当前库搜索与全局搜索

- 知识库内的搜索入口明确标识当前库，默认只搜索该库。
- 知识库外提供独立的全局搜索入口，范围为当前身份实际可读的知识库。
- 两个入口复用同一搜索接口与检索服务，通过已有知识库筛选条件表达范围；不复制
  两套引擎、索引或权限规则。
- 当前库无结果时不自动扩大到全局；切换结果不丢失当前工作区上下文。

管理网页继续使用管理会话，Agent 继续使用自己的设备凭据；复用搜索能力不要求
浏览器暴露 Agent Token，也不放宽任一接口的鉴权方式。

## 每个知识库独立的 Skills

每个 Library 有自己的 Skills 集合，可包含多个有名称、用途说明的 Skill。一个
Skill 是一个文件包，包含 `SKILL.md`、JSON、脚本、参考文档及其他附件，须能表达
`scripts/`、`references/` 等包内目录。

Skills 在产品层直属知识库，不为每个 Skill 创建供用户管理的占位 Section、Book
或单页书籍。首版各库独立，不做跨库共享引用或修改联动。

网页支持查看内容、源码编辑、保存、复制和下载。README 中的 Skill 链接在人类
浏览器中直接进入详情；已登录管理员可管理，不需要另粘贴设备 Token 才能查看。
Agent 仍可发现和下载同一个 Skill 的文件清单及全部文件。浏览器详情与 Agent
下载采用各自的鉴权入口，不把原始鉴权 JSON 清单当成人类阅读页面。

Skill 的自定义内容保存在实例的持久数据中，保存后即提供新版本，无需重新发布
应用镜像。保留可回看的不可变版本；恢复旧内容也形成新版本，不覆盖旧记录。
沿用库级独立 read/write 授权，不因读取说明扩大权限。服务器只保存、预览和分发
文件，不执行包内脚本。

现有 Page 强制归属 Section/Book 且文件名为平面结构，不能把它直接当作已完成的
Skill 模型。可复用完整快照、摘要、版本、并发和幂等机制；表结构、资源路径、备份
及旧内置 Skill 的兼容方式另行设计，不放松普通 Page 的既有约束。

## Skill 正式安装与线上版本同步

支持将 Skill 正式安装到宿主 Agent 可发现的技能目录，保留名称触发和渐进加载；
不能仅提供临时读取缓存来替代安装。线上发布版本是知识库规则的正式来源，本机
使用的是已安装版本，不是另一份互不相关的配置。

每个 Skill 提供版本信息、更新时间及逐文件摘要；发布包及本机安装记录应能识别
对应的线上版本，不能只在服务器界面显示版本号。README 的使用入口关联当前
Skills 与最新版本；版本摘要由系统生成，不要求用户在每次保存后手动维护第二份
版本号，也不改写用户的 README 正文。

每次新任务首次访问该库时，Agent 必须读取线上 README 和 Skill 版本信息，再与
本机安装信息比较。版本相同可继续使用，不必重装或反复下载全文；有新版时按宿主
授权自行下载、校验并更新，不由服务器强制推送或远程执行安装。
同时保留显式重新下载安装的入口，不能将“无需重复安装”变成禁止主动重装。

本机规则修改通常应同步发布到线上。若本机修改与线上新版分叉，显示差异，由用户
决定合并或采用哪个版本，不静默覆盖、丢弃或反向上传。Token、入口与宿主私有配置
单独保存，不能写入公开 Skill 包或被普通更新覆盖。

**信任模型**：持有有效凭据者即拥有该凭据授权范围内的权限。管理员可以编辑 Skill，
Agent 在首次访问时按宿主授权下载并更新。本方案不为此另设签名链或把校验值绑定到
版本号的机制；凭据或管理会话泄露通过吊销、轮换处理，不是本机制的设计目标。
包内脚本是否需要在本机逐次确认，由宿主 Agent 自己的授权策略决定，本提案不另行规定。

版本标识格式、包路径安全规则、核对失败时的离线行为与具体安装回执仍待契约审查。
更新时间用于展示，不能仅凭客户端时间比较决定是否覆盖内容。

## 响应式布局与统一交互

手机、平板和桌面保留同等业务能力，通过布局适配实现，而非将移动端限制为只读，
并支持触屏操作：触控目标足够大，不依赖悬停，拖放操作都有菜单替代（细则见
[交互规范](admin-frontend-interaction.md#触屏与响应式)）。桌面目录可折叠，窄屏
使用目录抽屉；全局菜单响应式收敛，文本、按钮和文件信息不依赖横向拖动整个页面
才能使用。引用修改窗口在窄屏使用全屏面板。

弹窗适合确认和短操作，抽屉适合上下文属性与目录，长正文编辑保留完整工作区。
加载、成功、失败及结果未知各有清晰反馈；短过渡用于保持上下文，尊重减少动态效果
设置。颜色之外仍用文字、图标或边界表达状态，并保留键盘与焦点操作。

## 原型与必要验收

优先呈现知识库概览、分区阅读、Page/Skill 文本编辑和引用修改窗口，先验证操作
路径及信息层级，再推进迁移。前端技术路线沿用[已有技术提案](admin-frontend-stack.md)，
具体依赖与安全兼容仍按该提案验证。

视觉与交互的验收由维护者在桌面、平板和手机宽度下目视完成，自动化测试因此保持
精简：覆盖默认正文与标题（含共享测试向量）、明确保存保留附件、引用修改的核心路径、
两个搜索范围、库内 Skill 编辑与版本同步。优先复用现有接口和浏览器旅程，避免为
相同行为扩建重复矩阵；文案与展示细节使用轻量检查。正式实现仍须保留鉴权、历史
保真与迁移/备份的必要验证。

实现前的技术决定集中在[开放问题](../08-open-questions.md#知识库工作区与库内-skills)，
产品确认不等于接受未设计的数据库或公开 HTTP 契约；契约与实现在同一轮交付内完成。
