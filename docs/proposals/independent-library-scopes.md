# Agent Token 的独立读取与写入范围

状态：已接受方向，实施与验证随本提案对应的 Pull Request 交付。

## 问题与目标

一个 Agent 身份可以处理多个知识库。创建界面的单一“归属知识库”混淆了身份的
历史内部定位与实际授权范围；逐库勾选也不能表达自动包含未来知识库的权限。
本提案以两套独立范围替代该交互，不增加管理员权限，不改变文件存储或网络入口。

## 范围契约

读取和写入各有 `mode` 与知识库 ID 选择集，两项完全独立：

| 前端名称 | 模式 | 集合含义 | 空集合 | 未来新建知识库 |
| --- | --- | --- | --- | --- |
| 仅指定知识库 | `include` | 允许的知识库 | 无此项权限 | 不自动允许 |
| 所有知识库（可排除） | `exclude` | 排除的知识库 | 全部允许 | 自动允许 |

默认读取和写入均为 `include` 空集合。全部读写等价于两个 `exclude` 空集合，
不增加第三种模式。例如读取 `exclude []`、写入 `include [A]`，允许读取所有
现有及未来知识库，仅允许写入 A。写入不隐含读取。

选择以稳定 ID 保存；重命名不影响范围。排除范围只授权实际存在的目标知识库，
不能使不存在的 ID 成为有效资源。凭据到期、撤销、轮换或身份停用仍先于范围判断。
主 Token、凭据签发、部署、备份恢复与任意 SQL 执行均不属于内容写入权限。

## 前端

创建及编辑复用两张独立权限卡：“读取范围”和“写入范围”。每张卡有模式选择、
可搜索的知识库复选列表、已选数量及权限摘要。选择器支持多选与清空，展开后直接
使用复选框，不要求按住键盘组合键。列表过滤只影响显示，不隐式取消隐藏选项。

模式切换不提交、不静默修改其他权限卡，界面明确标识当前列表为“允许”或“排除”，
并提示未来知识库的行为。保存为一个原子操作，两项同时提交；旧表单不能覆盖后续
修改。创建时不再要求用户选择归属知识库，列表和详情不再把内部归属呈现为权限。

## 兼容与持久化

新增迁移 `20261019_0032`，在既有逐凭据策略上增加 `read_mode`、`write_mode`
和单调 `scope_revision`。原始逐库条目复用为各动作的选择集；`include` 时是允许项，
`exclude` 时是排除项。旧策略迁移为 `include`，现有条目原样保留，不扩权。
没有逐库策略的旧 Section 凭据保持原有语义。

现有 Caller、凭据和审计关系继续保留内部 Library 定位，避免重写历史复合外键。
新界面不提交该字段；服务端按创建时间与 ID 的稳定顺序选择一个现有知识库作为
兼容定位，不因此授予访问权。尚无知识库时，界面提示先创建知识库，服务端也拒绝
无目标的签发；不为此创建用户不可见的系统知识库。全局身份彻底解耦不在本次范围。

轮换必须复制模式和原始选择集，不能复制当前有效授权清单。模式与选项整体编辑
使用 `scope_revision` 做并发检查，策略、审计和版本递增同事务完成。保留的旧逐库
编辑入口只适用于从未通过新范围编辑器修改、且两个模式均为 `include` 的凭据；
遇到排除模式或已有整体范围修改审计时返回冲突，避免旧表单反向授权或 ABA 覆盖。
即使后来切回 `include`，也须继续使用整体编辑器。旧入口成功修改同样递增范围版本。

备份验证识别新增模式、版本及精确结构，继续验证旧版本备份。存在 `exclude` 策略时
拒绝降级到不理解该语义的版本；不得丢弃排除范围或将其解释为允许范围。

## 鉴权与发现

所有读取、文件集写入、标签、生命周期与搜索继续使用同一逐凭据策略判断。
有效授权清单按当前知识库动态计算；搜索先确定实际可读范围，之后再查询内容。
`whoami.library_grants` 保持当前有效授权清单，另提供两项范围的模式和选择集，
帮助客户端区分当前权限与未来知识库行为。旧客户端忽略新增字段仍可使用当前清单。
旧接口的功能限制不因扩大授权范围而消失。

## 验证清单

- 两动作模式的四种组合、空集与多选、读写独立、未知知识库及默认拒绝。
- 签发后新建库的动态授权；排除、重命名、轮换、过期、撤销和停用。
- 旧 Token 无扩权迁移、备份与恢复校验、降级拒绝且业务数据完整。
- 整体编辑冲突、ABA、旧表单拒绝、审计失败回滚。
- whoami、发现、搜索、文件读写及标签的实际 API 鉴权一致性。
- 创建和编辑的多选交互、过滤不丢选项、明确摘要、无知识库提示与 CSRF 防护。
