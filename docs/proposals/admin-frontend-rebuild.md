# 管理前端体验整改与重构（总览）

- 状态：提案中（Proposed）；技术路线与产品交互已获维护者确认，接口契约与阶段验收仍待逐项审查
- 范围：`/admin` 管理面板的界面、交互、前端工程与管理端 JSON 接口；同一轮交付还包括
  入口文件与写入时标题、文本编辑与引用调整、库内 Skills 三项内容与数据模型扩展，
  详见[工作区与库内 Skills 产品需求](library-workspace-and-skills.md)

纯前端迁移部分不改变 Agent 公开 API、凭据语义或部署入口；上述数据模型扩展对
Agent 公开 API 只做增量变化（例如可选的入口文件字段与提示），其契约先设计再实现，
与前端在同一轮交付，不单独拆分排期。

## 背景

管理面板目前由 Python 函数直接拼接 HTML 字符串，样式与脚本也以 Python 字符串
形式内嵌并经路由输出。这种做法在安全边界上很严格（CSP、CSRF、禁止缓存、Token
不进浏览器存储），但随着书籍、页面、文件组、版本、标签、移动、回收站和凭据等
功能陆续加入，界面的可用性与可维护性问题已经十分明显：

- 多数操作仍整页提交并刷新，已有小票抽屉和上传等局部交互尚未统一；
- 导航重复、分组混乱，内部实现概念（操作键、ETag、修订游标）直接暴露给用户；
- 时间固定以 UTC 显示，输入需要手写 RFC3339 文本；
- HTML、CSS、JS、多语言文案混在 Python 中，难以复用和迭代。

完整的问题清单与代码依据见[现状问题](admin-frontend-ux-audit.md)。

## 目标

1. 让日常管理（浏览、搜索、上传、改名、移动、恢复、标签、凭据）在不离开当前
   上下文的情况下完成，并获得清晰的结果反馈。
2. 让界面以用户所处的语言与时区呈现，不要求用户理解存储与重试的内部机制。
3. 让前端成为可独立开发、类型检查和测试的工程，便于人类与 AI 协作者迭代。
4. 保持 [ADR 0003](../decisions/0003-admin-web-console.md) 确定的安全边界不退化。

## 非目标

- 不把管理面板变成部署控制台，不新增主机、Docker、镜像或备份恢复权限；
- 不引入用户账号、多角色或新的凭据类型；
- 不改变已有 Agent 公开 API、MCP 或 Skill 契约中的既有行为；入口文件、库内
  Skills 等新增能力只做增量扩展；
- 不引入 Node 服务端运行时（不采用 SSR 框架）；
- 本轮不提供永久删除。

## 已确认的架构决定

以下决定于 2026-10-20 与维护者确认：

1. **前后端代码完全隔离**：Python 后端最终只提供领域服务、管理端 JSON 接口、
   Agent 公开 API/MCP，以及只读托管前端构建产物的静态文件；不再含任何 HTML、
   CSS、JS 字符串、服务端模板或服务端 Markdown 渲染。前端是 `web/` 下独立的工程。
   **运行时仍保持同源**：管理会话是 `SameSite=Strict` 的 Cookie，并校验同源 Origin，
   跨域部署会破坏这些边界，因此构建产物由本服务（或同源反向代理）提供，不引入 CORS。
2. **Markdown 渲染与预览全部在前端**：阅读与编辑预览使用同一个渲染器，不再提供
   “只渲染不保存”的服务端预览接口。服务端只负责写入时提取标题。
3. **入口文件与标题在写入时确定**，随版本保存；提取不到标题即“无标题”。不为旧数据
   增加读取时的兼容推断，没有入口文件的文档显示“无入口文件”。
4. **网页文本保存冲突时直接覆盖**，被取代的版本保留在历史中；Agent 公开 API 的既有
   并发契约不变。
5. **信任模型**：持有有效凭据者即拥有该凭据授权范围内的权限。凭据或管理会话泄露通过
   吊销、轮换处理，不为此在 Skill 分发上另设签名或版本绑定机制。
6. **前端迁移与库内 Skills、文本编辑、引用调整同一轮交付**，内部按依赖顺序推进。

## 必须保留的安全约束

无论新旧界面，以下约束不变：

- 管理会话仍为同源、签名、HttpOnly、SameSite=Strict 的 Cookie，默认 Secure；
- 所有写操作仍校验同源 Origin、有效会话与 CSRF 值；
- CSP 不放宽为允许内联脚本、`eval` 或第三方来源；前端资源全部由本服务同源提供；
- 管理员、Operator 与 Agent Token 不写入 localStorage、sessionStorage、
  IndexedDB、URL 或日志；一次性凭据结果继续禁止缓存；
- 管理端 JSON 接口只接受管理会话，不接受 Bearer 凭据；Agent 公开 API 也不接受
  管理会话 Cookie；
- Markdown 中的原始 HTML 不渲染，远程图片不加载，渲染结果经过净化。

新界面对 CSP 的具体要求与需验证项见[迁移计划](admin-frontend-migration.md#安全与-csp)。

## 开放问题

1. **ADR 处理方式**：单页应用需要在全部 `/admin` 页面允许 `script-src 'self'`，
   并新增管理端 JSON 接口，后端不再渲染任何页面。这是对 ADR 0003 的补充还是需要
   新的 ADR，待审查决定。
2. **Operator Token 的呈现**：当前有两种登录身份。主 Token 会话执行全部网页写操作
   无需额外 Token；旧密码会话（尚未设置主 Token）下，标签写入和 Archive 类型页面
   的回收站恢复还须按次填写该知识库的 Operator Token（管理员 bearer Token）。
   建议新界面只让主 Token 会话可写，旧密码会话只读并引导设置主 Token，这样新界面
   不需要 Operator Token 输入框。若仍要支持旧密码会话写入，则需要一个按次输入、
   不存储的 Token 对话框。待维护者确认。
3. **入口文件的归属与补指定**：入口文件是随版本保存的属性（便于标题与历史保真，
   当前倾向），还是页面上的可变设置？单文件文档是否由服务端在写入时自动记为入口
   文件？为没有入口文件的旧页面“设为入口文件”是否生成一个新版本？
4. **既有独立标题的去向**：Agent 创建页面的接口目前要求 `title` 字段，网页也有
   “编辑 Page 标题”。标题改为写入时由入口文件一级标题派生后，这个字段是废弃并
   忽略，还是保留为可选？维护者当前倾向：提取不到标题即“无标题”。搜索投影如何更新
   也随之确定。
5. **Agent API 的增量形式**：可选的入口文件字段、未指定时的提示放在响应的哪个位置，
   需沿用现有的“接受并附带提示”风格（例如声明时间缺省时的提示）设计。
6. **文本编辑与引用调整的接口契约**：管理端如何表达“基于最新版本覆盖保存”，以及
   Markdown 引用的解析语法、行列位置与建议失效规则。
7. **旧页面下线时机**：新界面功能对齐后，旧页面保留多久、是否提供切换开关，待
   迁移后期决定。
8. **前端工程目录名**：暂定仓库根目录下的 `web/`，待审查确认。
9. **公开接入页**：`/connect` 及其脚本由 Agent 公开 API 一侧提供，不属于管理面板。
   本轮保持不变，是否迁移到前端工程另行决定。
