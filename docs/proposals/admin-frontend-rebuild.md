# 管理前端体验整改与重构（总览）

- 状态：提案中（Proposed）；技术路线已获维护者认可，具体契约与阶段验收仍待逐项审查
- 范围：`/admin` 管理面板的界面、交互、前端工程与管理端 JSON 接口；不修改内容
  模型、Agent 公开 API、凭据语义或部署入口

后续已确认的[工作区与库内 Skills 产品需求](library-workspace-and-skills.md)补充本文：
全局导航上移、概览与分区阅读分层、文本编辑及库内 Skill 管理。纯前端迁移继续复用
现有领域服务；新增 Skill 的实体、文件路径与 Agent 下载接口属于独立领域扩展，
须先完成模型、公开契约和迁移审查，不能按本文的前端范围直接改库。

## 背景

管理面板目前由 Python 函数直接拼接 HTML 字符串，样式与脚本也以 Python 字符串
形式内嵌并经路由输出。这种做法在安全边界上很严格（CSP、CSRF、禁止缓存、Token
不进浏览器存储），但随着书籍、页面、文件组、版本、标签、移动、回收站和凭据等
功能陆续加入，界面的可用性与可维护性问题已经十分明显：

- 多数操作仍整页提交并刷新，已有小票抽屉和上传等局部交互尚未统一；
- 导航重复、分组混乱，内部实现概念（操作键、ETag、修订游标）直接暴露给用户；
- 时间固定以 UTC 显示，输入需要手写 RFC3339 文本；
- HTML、CSS、JS、多语言文案混在 Python 中，难以复用和迭代。

完整的问题清单与代码依据见[现状问题](admin-frontend-ux-audit.md)。

## 目标

1. 让日常管理（浏览、搜索、上传、改名、移动、恢复、标签、凭据）在不离开当前
   上下文的情况下完成，并获得清晰的结果反馈。
2. 让界面以用户所处的语言与时区呈现，不要求用户理解存储与重试的内部机制。
3. 让前端成为可独立开发、类型检查和测试的工程，便于人类与 AI 协作者迭代。
4. 保持 [ADR 0003](../decisions/0003-admin-web-console.md) 确定的安全边界不退化。

## 非目标

- 不把管理面板变成部署控制台，不新增主机、Docker、镜像或备份恢复权限；
- 不引入用户账号、多角色或新的凭据类型；
- 纯前端迁移不改变已有 Agent 公开 API、MCP 或 Skill 契约；库内自定义 Skill 的
  新增能力按上述关联提案单独审查；
- 不引入 Node 服务端运行时（不采用 SSR 框架）。

## 方案：大小两条线并行

| 线 | 内容 | 文档 |
| --- | --- | --- |
| 小修 | 在现有 Python 页面上做低成本、高收益的修正，立即缓解最影响使用的问题 | [小修清单](admin-frontend-quick-fixes.md) |
| 大改 | 新建 React + TypeScript 单页应用，由 FastAPI 同源提供，逐页替换旧页面 | [技术选型](admin-frontend-stack.md)、[交互规范](admin-frontend-interaction.md)、[迁移计划](admin-frontend-migration.md) |

两条线的文件归属分开：小修只修改现有 `src/patchouli_lib/admin/` 下的页面与
路由；大改新增前端工程目录和独立的管理端 JSON 接口模块。旧页面最终会被替换，
小修不在其上做大规模重构。

## 必须保留的安全约束

无论新旧界面，以下约束不变：

- 管理会话仍为同源、签名、HttpOnly、SameSite=Strict 的 Cookie，默认 Secure；
- 所有写操作仍校验同源 Origin、有效会话与 CSRF 值；
- CSP 不放宽为允许内联脚本、`eval` 或第三方来源；前端资源全部由本服务同源提供；
- 管理员、Operator 与 Agent Token 不写入 localStorage、sessionStorage、
  IndexedDB、URL 或日志；一次性凭据结果继续禁止缓存；
- 管理端 JSON 接口只接受管理会话，不接受 Bearer 凭据；Agent 公开 API 也不接受
  管理会话 Cookie。

新界面对 CSP 的具体要求与需验证项见[迁移计划](admin-frontend-migration.md#安全与-csp)。

## 开放问题

1. **ADR 处理方式**：单页应用需要在全部 `/admin` 页面允许 `script-src 'self'`，
   并新增管理端 JSON 接口。这是对 ADR 0003 的补充还是需要新的 ADR，待审查决定。
2. **Operator Token 重复输入**：非主 Token 模式下，每次标签变更或恢复都要重新
   输入 Operator Token。是否允许在单个标签页的内存中短时保留，属于安全设计变更，
   需单独提案。
3. **文本编辑实现契约**：已确认支持文本源码与预览、点击保存形成完整文件组版本并
   保留未改附件，不建设自动保存/草稿系统；具体管理接口、派生标题、主文档选择和
   既有数据兼容需结合内容模型确定，见上述产品需求与决策台账。
4. **旧页面下线时机**：新界面功能对齐后，旧页面保留多久、是否提供切换开关，待
   迁移后期决定。
5. **前端工程目录名**：暂定仓库根目录下的 `web/`，待审查确认。
