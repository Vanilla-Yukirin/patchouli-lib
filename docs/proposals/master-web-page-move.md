# 同库 Page 移动

- 状态：提案中（Proposed）。Page 移动且不复制历史的产品方向已接受；本文件描述
  下一开发切片的建议边界，不发布稳定的 HTTP 或存储契约。
- 当前进度：归属移动尚未实现。历史恢复已在开发分支接通，但旧成功回执仍要求原
  Section／Book 路径；不能以恢复测试已通过推断移动兼容。
- 首片范围：主 Token 管理会话将未删除 Page 移到同一 Library 的另一本 Book，
  可以跨 Section；不跨 Library，不移动回收站 Page，不重组或删除 Book／Section。
  Agent 侧移动及稳定反查接口须另行记录，不代表总产品目标被取消。

## 用户操作与原成功重试

当前 Page 页提供“移动文档”。使用普通选择框选目标 Section 和 Book，显示当前
归属、目标归属与明确确认；不要求重新上传文件。提交当前强 ETag 和独立的本次
操作键，响应丢失后的刷新与重试保留原请求，不能自动换成新操作。

移动保持 Library、Page ID、内部 UID、声明时间、标题、Tag、当前 Revision、全部
历史文件与 Source 不变。只有当前 Section／Book、单调递增的更新时间及归属审计
变化；不新增内容 Revision。目标等于当前归属时成功提示“未移动”，不增加移动
事件或内容活动，但仍保存成功记录，否则同键在后来重试可能意外变成真正移动。

新操作拒绝错误库、错误目标、已删除 Page、旧 ETag 和已失效主会话。原成功在以后
的修订、移动或删除后重试，只返回当时的结果，不再次移动、不覆盖新归属，也不
移出回收站。历史结果不应被措辞成“现在所在的位置”。操作键命名空间为主身份、
移动动作与键摘要，不能因重登换会话而丢失原结果；指纹绑定源／目标完整路径、
Page ID 与原 ETag。当前鉴权始终先于成功重放。

浏览器沿用当前同标签页 `sessionStorage`：先保存原源／目标、ETag 与键，再发请求；
存在未确认结果时锁定目标选择，刷新不采用新归属替换原请求。此方式不承诺关闭标签页
或跨设备后自动恢复浏览器记录；服务端成功记录才是持久重放依据。原深层路径因后续
移动或删除而不可用时，已鉴权的 404 页面保留安全重试 shell，无原记录则不允许新写。

## 不可变归属历史与事务

现有成功回执、旧 Caller 响应、主内容活动及备份验证将历史路径与当前路径对照。
只更新 `pages.section_id/book_id` 会把合法历史判为损坏；取消对照又会接受错误路径。
移动必须保留可验证的准确归属历史，再按对应的历史逻辑状态证明原路径。

拟增加不可变移动事件与独立持久成功记录。事件保存稳定 Page 身份、连续序号、
原／新 Section 与 Book、旧更新时间、严格递增的移动时间、当时 Revision 和
声明时间，以及唯一真实主审计 ID。原／新 Book 都须属于准确的同库 Section；
事件不可修改或删除，旧数据不回填虚构移动。

实现前比较两种可靠方案：复用标题编辑的审计保护模式，由触发器核对唯一未消费的
主审计并从准确 OLD／NEW 写事件；或者使用必须完整消耗的临时 guard。优先减少
新表，但必须同样保证直接无审计更新被拒绝、不夹带标题／时间／版本／删除变更、
精确归属与逻辑时钟、事件插入失败原子回滚，以及孤立审计失败关闭；不能仅为少一表
放松校验。准确表形、触发器和成功记录结构仍待迁移前审查。

一次移动在一个 `BEGIN IMMEDIATE` 内复核会话代次、源与目标归属、ETag，写主审计、
条件更新、不可变事件及成功记录，并维护就绪搜索索引；任何一项失败均回滚。
服务器原始时钟可以落后于已有逻辑更新时间，移动时间必须单调推进。

## 历史路径、权限与链接

历史路径 helper 校验完整连续链的初始归属、每一步衔接及最终当前归属，不能仅
因为某个路径“曾经出现过”就接受。主文件集回执按 `original_page_updated_at`
对应状态证明原路径，不能只用原始 `operation_at`；Agent no-op 回执只有 ETag，
必须共同证明其历史版本、活动状态与准确归属，不能单独放宽路径。

移动后的重放仍先核对当前身份及实际可访问的目标。逐 Library 授权不因同库移动
变化；旧 Section 凭据不因曾访问原分区就有权读取新的分区。新增键使用当前归属，
旧键仅凭真实原请求指纹和完整历史证明回读原结果。

旧 Revision、Source、审计及响应不改写。近况以历史路径验证事件，以受保护当前
位置链接准确版本，不把已删除内容泄露出来。主会话可按 Library／Page ID 解析
当前位置，仍核对登录和删除状态；Agent 稳定反查的形状另议，不通过公开重定向
泄露位置。旧深层 URL 不自动承诺长期重定向。

建议主会话稳定入口为 `/admin/libraries/{library_id}/pages/{page_id}` 及其
`/revisions/{revision_number}` 子路径，直接渲染而非公开重定向；一次真实读取快照内
完成主身份复核、稳定身份解析与准确版本读取。它只供导航，不修改已冻结的写请求。
既有管理文件集响应的 `revision_url` 含历史原路径，须明确保留原字段另加稳定链接，
或单独记录管理端改版；不能把原成功响应悄悄改成当前路径。

历史恢复的源快照预读取同样必须处理原路径证明，否则即使成功回执已兼容移动，
重试也会在进入回执查找前被当前路径检查拒绝。活动验证、回执验证、读取 gate 和
准确导航须一并验收，不能只修持久回执的一处比较。

## 备份与迁移前置

备份按准确修订号决定结构哈希和可用特性，而不是把“当前默认修订”当作某一历史
特性的代名词。先显式固定主校时的 `20261001_0027` 格式，保持 `0026` 及 `0027`
的真实结构、哈希和恢复分支不变；不存在的下一格式不能提前被接受。默认创建格式
仍是当前支持的 head；旧备份始终显式指定原修订号，不自动升级。

后续移动迁移需将移动事件纳入逻辑更新时间重建、生命周期历史、主／Caller 回执
以及内容活动路径校验。存在移动事件、未消耗 guard 或孤立移动审计时不得有损降级。
不伪造初始归属、重写旧回执或跳过旧 Caller 授权验证来通过备份。

## 验证清单

- 同 Section 换 Book、跨 Section、多次往返及同目标无变化；完整身份、历史和字节不变。
- 错误库／目标、旧 ETag、并发修订／校时／轮换／删除，及全部失败原子回滚。
- 原成功在后续移动或删除后准确重放；移动前后主／Caller 历史及 no-op 路径证明。
- 当前权限拒绝对照，旧 Section grant 不扩权，搜索与活动链接采用准确当前位置。
- 审计或索引维护失败整体回滚，孤立或篡改移动链失败关闭。
- `0026`／`0027` 精确旧格式仍可验证恢复；新移动格式混合历史往返及有损降级拒绝。
- 经典原生表单、明确确认、普通 HTTP、响应丢失及持久原键重试。

本提案不授权已有服务更新、真实数据搬移或永久删除，不改变其他提案状态。
