# 下一阶段改造清单

本清单只列工作项，不代表功能已经实现或设计提案已经获得兼容性批准。具体目标、
边界、待决定事项和验收证据见[下一阶段产品与接口设计](proposals/next-phase-product-and-api.md)。
统一上传的候选请求与响应另见[统一文件集 HTTP v1 草案](proposals/unified-file-set-http-v1.md)；
该草案尚未获接受；当前开发分支已注册文件集路由，但尚未合并或部署。
实施时应按依赖拆分成可审查的改动，不要求一个 Pull Request 完成全部程序修改。

- [ ] 核对现有数据、公开接口、客户端和管理面板的兼容性边界。
- [ ] 确认多文件 Page、搜索索引、凭据保存与多 Library 授权的详细方案。
- [x] 确认新客户端以统一文件集模型处理单 Markdown 与多文件 Page；具体 HTTP 契约仍待审查。
- [ ] 为数据库迁移、索引重建、备份恢复和旧客户端制定回退路径。
- [ ] 更新公开提案的状态与决策记录；未经接受不启用生产索引迁移。

## 凭据、授权与审计

- [ ] 设计单人主 Token 的首次设置、遗失恢复、旧密码／operator Token 兼容期，
      以及会话签名与主 Token 轮换后的旧会话失效。
- [ ] 实现 Agent／设备身份、凭据展示、复制、轮换和吊销；新 Agent Token 明文仅存
      SQLite 独立受限表，主 Token 仅存不可逆校验值，旧 Token 不假设可还原。
- [x] 在开发分支增加 0015 独立 Agent Token 明文表；新签发值与校验值同事务保存，
      旧值不回填，吊销／轮换／停用后不再提供当前值；备份校验保留 0014 兼容。
- [ ] 实现管理会话保护的单独 POST 明文显示接口，并验证同源、CSRF、凭据状态、禁止缓存、
      审计脱敏和默认页面不预载明文。
- [ ] 将数据库、WAL、备份和恢复流程按含有明文 Agent Token 的机密材料验收，

- [x] 在开发分支增加未激活的逐凭据 Library 授权存储与 0014 迁移；

- [ ] 实现每个凭据对多个 Library 的读／写开关，不细分 Section。
- [ ] 扩充调用方身份查询，展示名称、说明与有效权限。
