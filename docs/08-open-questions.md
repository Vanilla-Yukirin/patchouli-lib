# 开放问题

以下决定尚未解决。实现可以试验一种答案，但在没有公开提案的情况下，不得把该答案
描述为稳定的项目契约。

维护者已经明确下一阶段要支持多文件 Page、可跨 Library 的设备凭据、真正的字符
倒排搜索和更完整的管理后台。这些是已记录的**产品目标**，详见
[下一阶段提案](proposals/next-phase-product-and-api.md)；它们不表示存储格式、
安全迁移、索引方案或对外 API 已经接受，也不能把下面尚未解决的技术问题直接勾选。

## 实现证据如何影响本台账

未勾选事项可以已有范围有限的实现和测试，但这并不构成稳定的兼容性承诺。当前仓库
包含若干此类情况：

- HTTP 服务已有结构化错误、签名游标分页和幂等创建/修订接口，但完整公开 API 和
  兼容性策略仍然开放；
- 当前持久化路径已经实现 Page ID 生成和冲突处理，但
  [稳定标识符与引用](06-identifiers-and-references.md)中影响兼容性的语法仍有部分开放；
- 已实现限定 Section 的授权、凭据到期、恢复和吊销，但更广泛的策略维度及允许/拒绝
  优先级仍然开放；
- 实验性 SQLite 备份、校验和“恢复到全新目标”代码已有自动化证据，但
  [备份、恢复与升级提案](proposals/sqlite-backup-restore-and-upgrade-alpha.md)
  仍处于 **提案中（Proposed）**，并非受支持的恢复策略。

以下复选框记录公开决定，而不是是否已有代码。

## 知识库工作区与库内 Skills

[产品需求](proposals/library-workspace-and-skills.md)已确认顶部全局导航与分区目录分工、
概览/阅读分层、明确保存、入口文件与写入时标题、可选择的引用调整、当前库/全局搜索入口，
以及每库独立的多文件 Skill 和本机正式安装同步。这些与前端迁移在同一轮开发中交付，
但各项契约仍须先于实现定出。

已确认的取舍（2026-10-20）：

- [x] Markdown 渲染与预览全部在前端，后端不再渲染页面，也不提供服务端预览接口。
- [x] 标题在写入时由入口文件的第一个一级标题确定并随版本保存；提取不到即“无标题”。
- [x] 入口文件显式指定；Agent 未指定时接受写入并提示。2026-10-21 补充：仅缺少
  新版展示记录的旧归档采用管理端只读入口／标题推导；显式未选入口的版本不改变。
- [x] 网页文本保存遇到更新版本时直接覆盖，被取代的版本保留在历史中。
- [x] 持有有效凭据者即拥有对应权限；Skill 分发不另设签名或版本绑定机制。
- [x] 取消旧密码会话，只保留主 Token 会话；新界面没有 Operator Token 输入框。

本轮已由[实现契约](proposals/workspace-implementation.md)与
[ADR 0005](decisions/0005-library-workspace.md)确定的技术决定（实现验收另行记录）：

- [x] 入口随准确 Revision 保存；旧归档管理阅读按上述只读例外兼容，不回填历史。
  用户明确保存入口仍生成新版本。
  Agent 的 `primary_file` 可选，缺省提示保留在响应头。
- [x] Agent 既有 `title` 保留标识与协议兼容含义；网页展示使用保存的版本标题，
  检索采用该版本已有的展示记录，稳定 ID 和旧历史不变。
- [x] 定义文本编辑与引用调整的文件集修订契约，包括支持的 Markdown 语法、行列
  位置、共享引用定义的选择粒度，以及内容变化后如何使旧建议失效；管理端如何表达
  “基于最新版本覆盖保存”。
- [x] Python 与前端共用 `tests/vectors/revision-titles.json`，覆盖标题提取的关键规则。
- [x] 定义 Library 直属 Skill 的实体、目录路径、版本、授权审计及持久数据边界；
  区分结构/版本摘要与包内文件读取，明确仅写凭据的可见范围，不通过放松普通 Page
  的平面文件名或父级约束来隐式实现。
- [x] 定义管理员网页与 Agent 下载所对应的 Skill 身份、入口、manifest、并发、
  版本核对及本机安装回执；保持原有会话/Bearer 边界。
- [x] 内置通用 Skill 地址继续有效，库内自定义包独立持久化；新增表进入精确格式备份，
  不回填旧入口；管理阅读的只读兼容例外见上述补充。无法确认线上版本时不自动覆盖本机安装。
- [x] 取消密码会话后现有安装的过渡、一次性设置令牌保留、密码相关配置与命令的废弃
  节奏（见[前端总览开放问题 2](proposals/admin-frontend-rebuild.md#开放问题)）。

## 已接受方向

- [x] Page 正文使用不可变 Revision；恢复会创建新 Revision。
- [x] Page 在任意时刻属于一个 Book，移动时无需复制历史。
- [x] 一个 Book 可以只有一个 Page；Page 的展示标题不要求英文连字符命名。
- [x] Page 的全部文件字节与历史版本保存在 SQLite，不设外部权威文件目录；
  旧单 Markdown 接口不得静默丢弃新格式文件，见
  [ADR 0004](decisions/0004-page-file-storage.md)。
- [x] Tag 和 Shelf 是检索投影，不是内容所有者。
- [x] 模型提供方和部署位置由管理员配置。
- [x] 自动整理默认生成可供审查的建议。
- [x] 公开示例和工作流不含维护者专用基础设施。
