# ADR 0004：Page 文件字节保存在 SQLite

- 状态：**已接受（Accepted）**，仅限本文列明的存储方向
- 日期：2026-09-29

## 背景

下一阶段的 Page 可以包含同层的多份文件，也可以只有非 Markdown 文件。历史
Revision 必须能准确还原整组文件。把文件字节和版本元数据分放于数据库与外部目录，
会使一次写入、备份、恢复和回退跨越两个独立资源。

## 决定

- Page 的文件字节、文件清单和历史 Revision 均保存在 SQLite；不另建外部对象目录
  作为权威内容存储。
- 每个 Revision 表示完整的平面文件集。现有单 `content.md` 历史数据继续可读，
  新格式允许完全没有 Markdown；不得用占位 Markdown 冒充文件内容。
- 旧的单 Markdown 接口遇到无法表达的新文件集时，应返回明确的“不支持该格式”
  错误，不得静默遗漏其他文件。
- 新格式只有在数据库迁移、完整写入事务、准确读取和备份验证共同通过合成数据
  验收后，才能开放写入。已存在的数据和线上服务不因本决定自动迁移。

## 尚未决定

文件名、类型、大小配额、清单摘要、Source 语义、同页相对引用、下载预览安全、
旧客户端错误码及实际迁移／恢复步骤仍需分别审查。本 ADR 不接受整份
[下一阶段提案](../proposals/next-phase-product-and-api.md)，也不把实验性备份能力
升级为已支持的正式恢复策略。
